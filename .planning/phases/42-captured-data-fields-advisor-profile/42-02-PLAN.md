<objective>
Add the three storage primitives the rest of Phase 42 depends on — `users.telephone` (PROF-01),
`users.company_telephone` (FIELD-02 / D-13) and the `leasetic_advisor` singleton table (PROF-03 /
D-07 / D-08) — generate the migration, and get an operator to apply it to production **before any
other plan registers a Better Auth `additionalField`**.

Purpose: this repo has already shipped the inverse ordering once. Better Auth's Drizzle adapter
issues a `SELECT` naming every column registered in `user.additionalFields`, so deploying the
registration ahead of the migration 500s **every authed page** with `APIError: Failed to get
session` (RESEARCH R2, Pitfall 1). Making the migration a separate plan with a blocking operator
checkpoint is what makes the ordering structural rather than a comment someone can miss.

Output: an amended `src/db/schema.ts`, a committed `drizzle/0011_phase42_captured_data.sql`, a
journal entry in sync with it, and an operator-confirmed `MIGRATE PROD` run.
</objective>

contact details out of `params_snapshot` and (b) a fixed-id UPDATE is race-safe without a lock,

singleton. Also record D-09: the row is read live at render time and is never snapshotted into
`proposals.inputs`.
