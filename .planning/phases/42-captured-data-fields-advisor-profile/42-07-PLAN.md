## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-07-A | Elevation of Privilege | `/{adminSegment}/advisor` page | mitigate | Three independent gates: the layout's segment-obscurity `notFound()`, the layout's `requireAdmin()`, and this page's own `await requireAdmin()` (AUTH-15 defence in depth). The real authorization gate is `requireAdmin()` inside `adminUpdateAdvisor` (T-42-06-A) — the page guard only prevents rendering, never the write. |
| T-42-07-B | Information Disclosure | admin URL secrecy | mitigate | The route 404s rather than 403s for non-admins, so a guesser cannot distinguish "exists but forbidden" from "does not exist" (AUTH-14). `metadata.robots` is `{ index: false, follow: false }`, matching the sibling admin pages. |
| T-42-07-C | Information Disclosure | save-failure surface | mitigate | The form renders only the bounded `admin.advisor.toast.error` key and never echoes the action's returned error string, matching the app-wide generic-fallback pattern. |
| T-42-07-D | Information Disclosure | ADMIN-09 envelope | mitigate | The four fields and the new nav card carry only contact and chrome copy. `tests/admin-09-grep-contracts.test.ts` runs in this plan's verification rather than being assumed inert. |
| T-42-07-E | Tampering | client-side validation bypass | mitigate | `advisorFormSchema` is re-parsed server-side inside `adminUpdateAdvisor` (Plan 42-06), so a caller that skips the form still fails the identical rule. |
| T-42-07-SC | Tampering | npm/pip/cargo installs | accept | No packages installed; UI-SPEC § Registry Safety records zero new shadcn/ReUI blocks — every primitive used is already vendored. |
