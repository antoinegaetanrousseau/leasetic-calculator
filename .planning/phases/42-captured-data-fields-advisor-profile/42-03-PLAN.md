## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client form → `proposalInputSchema` | Untrusted partner input crosses into the draft's `inputs` jsonb |
| `finalizeWizard` → `proposalInputSchema` | The same untrusted stored input is re-parsed server-side before compute and render |
| recherche-entreprises API → `registrySchema` | Third-party payload crosses into application types |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-03-A | Tampering | `clientSiret` in `proposals.inputs` | mitigate | The rule lives once in `proposalInputSchema`, imported by both the RHF resolver and `finalizeWizard`'s `.parse()`. A tampered client that skips the form still fails the identical server-side re-parse (ASVS V5). |
| T-42-03-B | Tampering | third-party registry payload | mitigate | The new `siret` field is Zod-parsed with the same `truncated(CODE_MAX).pipe(z.string().max(CODE_MAX))` bound every sibling uses, so an oversized or non-string upstream value is rejected rather than propagated. `.nullish()` keeps a single absent field from failing the whole payload. |
| T-42-03-C | Information Disclosure | new i18n message keys in schema | mitigate | `error.field.siret.mismatch` is a bare dictionary key, not an interpolated value — no SIREN, SIRET or partner data is embedded in any validation message. |
| T-42-03-D | Denial of Service | `partnerTel` requiredness | mitigate | `partnerTel` is optional by construction (D-13). Making it required would hard-block every existing partner behind a fix only an admin can perform; the test asserting an omitted `partnerTel` parses is the regression guard. |
| T-42-03-SC | Tampering | npm/pip/cargo installs | accept | No packages installed; `42-RESEARCH.md` § Package Legitimacy Audit records the phase as install-free. |
