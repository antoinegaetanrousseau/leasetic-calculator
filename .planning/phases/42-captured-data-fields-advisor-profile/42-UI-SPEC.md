# Phase 42 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**No RESEARCH.md exists for this phase** (research disabled in this project's config). All stack
facts below are derived directly from the codebase, not from a research document.

**Scope note.** This phase captures data only; it renders nothing into the PDF (Phase 43 owns
the card layout, DOC-11 em-dash treatment and the type scale). The four web surfaces in scope
are: (1) the proposal wizard step-1 client card, (2) `/parametres`, (3) the admin partner
create/edit form, (4) a new admin advisor-identity settings surface — plus one new dialog (the
finalization profile-completeness block, D-18).

**Every locked decision below is cited to its `D-NN` in `42-CONTEXT.md`. Do not reopen any of
them — this document only supplies the visual/interaction contract those decisions still leave
open (copy, layout placement, component choice, states).**

## Spacing Scale

Per **UIC-01** (`.planning/codebase/UI-CONVENTIONS.md`) — the project-wide ratified exception:
Tailwind's native 4px-step scale used directly at every call site, including 12/20/28px steps
the generic GSD default omits. Every value used on this phase's surfaces must divide evenly by 4.

| Token | Value | Usage on this phase's surfaces |
|-------|-------|-------|
| xs | 4px | Asterisk-to-label gap (`ml-0.5`) on required-field markers |
| sm | 8px | Icon-to-label gaps inside `InputGroup` addons |
| md | 16px | 2-column row gap (`gap-4`) — e.g. Prénom/Nom, and the new admin téléphone rows |
| lg | 20px | `FieldGroup` vertical rhythm inside wizard/admin form cards (`gap-5`) |
| xl | 24px | `<hr>` section dividers inside the wizard card and the admin partner-form card (existing pattern, reused verbatim — do not introduce `FieldSeparator` in cards that already use the `<hr>` convention) |
| — | 16px | `.card` container radius/padding baseline (`--radius-container`, UIC-04) |

Exceptions: none. This phase introduces no sub-4px or non-multiple-of-4 literal.

## Color

Per **UIC-03** (one accent, 60/30/10, per-surface reserve list — never "all interactive
elements"). Derived mechanically per the file's own method: `app/globals.css` aliases
`--primary`, `--ring`, `--sidebar-primary`, `--sidebar-ring`, `--gd`, `--gd-text`, `--green` to
`--brand-accent` (`#01cc72`).

| Role | Token | Share |
|------|-------|-------|
| Dominant | `--background` | 60% |
| Secondary | `--card` | 30% |
| Accent | `--primary` / `--brand-accent` (`#01cc72`) | 10% |
| Destructive | `--destructive` | Errors only (SIRET/SIREN mismatch, required-field markers) |

**This phase's accent reserve list (exhaustive):**

1. `SectionTitle`'s bullet on the wizard step-1 card and the admin partner form —
   `accent="gd"` (default) — **is** accent-colored. Unchanged from existing shipped surfaces.
2. `SectionTitle`'s bullet on `/parametres`' "INFORMATIONS PERSONNELLES" card —
   `accent="teal"` — is **not** accent. `--teal` aliases `--muted-foreground` (grey), per
   UIC-03's legacy-alias note. Do not treat the téléphone/fonction additions as accent-adjacent
   because of this bullet.
3. The new admin advisor-identity page's `SectionTitle` bullet — `accent="gd"` (matches the
   admin partner form's existing convention) — **is** accent.
4. Every text `Input`/`InputGroup` on all four surfaces — `:focus-visible` ring is
   `var(--ring)` = accent, per the shared `input.tsx` base class. This is chrome, not a
   per-surface choice; do not add a second focus treatment.
5. `.btn-green` primary submit CTAs — "Enregistrer les modifications" (`/parametres`),
   "Envoyer l'invitation" (admin partner form), and the new advisor page's "Enregistrer" — are
   accent. Every `.btn-out` / `Button variant="outline"` (Annuler, dialog dismiss) is **not**.
6. The new finalization dialog's primary CTA ("Aller à Paramètres" / "Go to settings") uses
   shadcn `Button` default variant, which resolves to `bg-primary` — accent. Its dismiss action
   uses `variant="outline"` — not accent.

Nothing else on these four surfaces carries the accent. Required-field asterisks (`*`) are
`text-destructive`, not accent — do not recolor them.

|-----|----|----|
| `form.client.siret` | SIRET | Establishment ID |
| `form.client.siret.placeholder` | 123 456 789 00012 | 123 456 789 00012 |

**2. `/parametres` — téléphone + fonction (`ParametresForm.tsx`, D-14/D-20)**

Both join the existing "INFORMATIONS PERSONNELLES" card, inside the `identityForm` (so they
share its dirty-tracking and the existing `parametres.toast.identity.saved` /
`parametres.toast.both.saved` combined-save copy — no new toast keys needed).

| Key | FR | EN |
|-----|----|----|
| `parametres.identity.telephone.label` | Téléphone | Phone |
| `parametres.identity.telephone.placeholder` | 06 00 00 00 00 | 06 00 00 00 00 |
| `parametres.identity.fonction.label` | Fonction | Role |
| `parametres.identity.fonction.readonly.notice` | Défini par votre administrateur. | Set by your administrator. |
| Phone error | reuses `error.field.phone.invalid` *(exists)* | (same) |

Layout: téléphone is a new **editable** row placed directly beneath the existing Prénom/Nom
2-column row (full-width `Field`, matching the email row's width). Fonction is a new
**read-only** row placed **beside the existing read-only email row** (per the required-reading
brief) — render it as a second full-width `Field` immediately after email, using the *exact*
static-`<p>` markup class string the email row already uses
(`m-0 rounded-xl border border-border bg-[var(--hover-overlay)] px-3 py-2.5 text-[14.5px]
text-ink`) plus the `readonly.notice` helper paragraph beneath it, mirroring
`parametres.identity.email.readonly.notice`'s treatment exactly. **Value is the raw
`partnerType` string** ("Agent" / "Commercial" / "Partenaire") — **do not translate it here**;
D-16's FR/EN label pair is scoped to the PDF only, and translating it on this surface would be
new, undecided scope (see Deferred in `42-CONTEXT.md`).

Téléphone is **optional** on this form (no asterisk) — PROF-01 lets a partner set it, it does
not require it be set before the form itself can save; **PROF-02**'s enforcement lives
exclusively at finalize (D-17), not here.

**3. Admin partner create/edit form (`CreatePartnerForm.tsx` + `src/lib/admin/schemas.ts`, D-13/D-19)**

The form already has ONE `phone` field, placed in "INFORMATIONS SOCIÉTÉ" beside `companyName`
and `siret` — that placement already matches where D-13 wants the **company** telephone to
live. This phase does two things to this surface:

a. **Relabel the existing `phone` field** (Section 2, company section) to disambiguate it now
   that a second phone field exists on the same form:

   | Key | Old FR | New FR | Old EN | New EN |
   |-----|--------|--------|--------|--------|
   | `partners.new.field.phone` | Téléphone | Téléphone (société) | Phone | Company phone |

   No placeholder change needed. This is the company telephone (D-13) — admin-set, nullable,
   never blocks finalization.

b. **Add a new field** to Section 1 ("INFORMATIONS PERSONNELLES"), placed directly after
   `email` and before `partnerType` — the partner's own téléphone (D-19):

   | Key | FR | EN |
   |-----|----|----|
   | `partners.new.field.telephone` | Téléphone | Phone |
   | `partners.new.field.telephone.placeholder` | 06 00 00 00 00 | 06 00 00 00 00 |

   Neither new/relabeled phone field carries a required asterisk — both columns ship nullable
   (D-13) and D-19 explicitly frames this as admins *proactively* filling gaps, not a hard gate
   on partner creation. If this phase adds a partner **edit** surface (none exists in the
   codebase today — only `partners/new/CreatePartnerForm.tsx` — a create form), it must carry
   the identical section placement, labels and optionality; do not invent different copy or
   layout for an edit variant.

**5. Finalization profile-completeness dialog (D-17/D-18)**

existing generic-toast catch-all. This is the **one** exception `FinalizeButton` must learn; every

**6. Legacy-draft finalize gap (D-05)**

returning to step 1 of *this* proposal, not by visiting `/parametres` — so it must not reuse the
dialog above. Surface it as a **toast** (not a dialog) naming the SIRET field, paired with a
redirect back to step 1 so the partner lands where the fix is:

| Key | FR | EN |
|-----|----|----|

Bounded code suggestion: `LegacyDraftIncomplete` (distinct from `MissingPartnerTelephone` and
from the existing generic `ValidationFailed`), added to `SAFE_ERROR_CODES`.

## Interaction & State Notes

- **SIRET registry prefill (D-01/D-03).** No live wizard-triggered registry lookup exists in
  the codebase today (`recherche-entreprises` is currently wired only into the CRM's background
  `registry-sync.ts` and the `/clients` dialogs' manual "search" actions, not the proposal
  wizard). Wiring the prefill call is implementation, not UI — but the **visual contract** is:
  no loading spinner is required by any locked decision; if the executor adds one, keep it to a
  subtle `InputGroup` inline affordance, never a blocking overlay, and never a "registry
  unavailable" message on failure (D-03 is explicit that the fallback is silent). The SIRET
  field stays editable at all times, prefilled or not.
- **Cross-field SIRET/SIREN validation (D-02)** fires on the same `mode='onBlur'` cadence the
  rest of step 1 already uses (inherited from the outer `ProposalFormProvider`) — no new
  validation trigger pattern.
- **Admin advisor page save** is a singleton upsert, not a create — the "Annuler" action
  resets the form to last-saved values (mirrors `ParametresForm.tsx`'s `handleCancel`), it does
  not navigate away (there is nothing to navigate back to; this is the page's only content).
- **Accessibility (project gate, not optional).** Every inline error on new fields uses
  `<FieldError role="alert">` (already the `FieldError` primitive's default — see `field.tsx`
  line 217). Any icon-only control this phase might introduce (none currently planned) must
  carry an explicit `aria-label` per **UIC-10**. Dialog focus/ring styling inherits `dialog.tsx`
  and `input.tsx` unchanged — no component-local hardcoded focus color, per **UIC-11**.
- **`TableCell` nowrap trap** does not apply to this phase — none of the four surfaces renders
  a `<Table>`.
