<constraints>
These are the D-36-03 constraints. They are the reason the probe is permitted to exist at
all — it reads the production `main` branch, which is the exact thing INFRA-05 forbids from a
local machine. It is permissible ONLY because it reads nothing but its own sentinel's absence.

- **Connection strings are passed explicitly and inline.** The probe reads its two URLs from
  process env vars supplied on the invocation. It must never open `.env.local`, must never
  `source` any env file, and must never call `dotenv`. In particular it must NOT
  `import './_load-env'` — every other `scripts/*.ts` entry point starts with that import,
  and the shim does `config({ path: '.env.local' })`, which is precisely what this
  constraint forbids. **State this divergence in the probe's header comment**, or a future
  maintainer will "fix" it back by adding the import.
- **The `main`-side step is a single existence check.** One
  `SELECT count(*) ... WHERE <sentinel column> = '<uuid>'` returning a count, never rows.
  No customer data is read. The `main` client must never execute an INSERT, UPDATE, DELETE
  or DDL statement.
- **The sentinel goes to a table where a stray row is harmless, and is deleted in the same
  run** via a guaranteed `finally`. Nothing is left behind on `development`.
- **Never print a full connection string, username or password.** Hostnames only. The
  output is expected to be pasted into a transcript and into Phase 29's artifacts.
- **Do not run the probe against a real database in this plan.** Only the synthetic
  safety-gate self-tests in Task 2 are executed here.

- Do not edit `eslint.config.mjs`.
