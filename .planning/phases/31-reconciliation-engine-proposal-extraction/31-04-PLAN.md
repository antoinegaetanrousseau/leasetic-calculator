<report_contract>
Claude's-discretion items from CONTEXT.md, fixed here and consumed by plan 07.

**Location:** `.reconcile/` at the repository root, git-ignored. Rationale: the report describes
real client names and partner identities from the live database — it must never be committable.

**Files written per dry run:**
- `.reconcile/dry-run-<ISO8601-basic>.json` — the serialized `ReconciliationPlan` wrapped in an
  envelope, archived, never overwritten
- `.reconcile/dry-run-<ISO8601-basic>.md` — the human-readable summary, archived
- `.reconcile/dry-run-latest.json` and `.reconcile/dry-run-latest.md` — copies of the two above,
  overwritten every dry run; `dry-run-latest.json` is the file the real run reads (D-15)

`<ISO8601-basic>` means `2026-09-02T141500Z` (no colons, safe on every filesystem).

**JSON envelope shape:**
`{ reportVersion: '1', sourceId, generatedAt, databaseFingerprint, counts: { companiesToCreate, companiesExisting, relationshipsToCreate, contactsToCreate, contactsToUpdate, proposalLinks, pairsFlagged, pairsSuppressed, skipped }, plan: <the full ReconciliationPlan> }`

`databaseFingerprint` is the SHA-256 hex digest of the `DATABASE_URL` **hostname plus database
name only** — never the full URL, never credentials. It exists so a real run can refuse to
consume a dry-run report generated against a different database.

**Markdown sections, in order:** title with source id and timestamp; a counts table; "Companies
to create"; "Companies matched to existing records"; "Relationships to create"; "Contacts to
create"; "Contacts to update"; "Pairs flagged for review" (with reason and both side keys);
"Pairs suppressed by an existing decision"; "Skipped rows" (grouped by reason, every row listed
with its source row id). Every section renders the literal count `0` and the sentence
`_None._` when empty — never omitted, because an omitted section is indistinguishable from a
section the writer forgot.
</report_contract>

  </read_first>
  <behavior>
    `computeDrift({ stored, fresh })` where `stored` is a `DryRunReportEnvelope` and `fresh` is a
    `ReconciliationPlan`:
    - returns `{ status: 'no-report' }` when `stored` is `null`
    - returns `{ status: 'fingerprint-mismatch', storedFingerprint, freshFingerprint }` when the
      two database fingerprints differ — the reviewed report describes a different database and
      must not authorize this run
    - returns `{ status: 'source-mismatch' }` when the two `sourceId`s differ
    - returns `{ status: 'clean', ageMs }` when the two plans are structurally identical apart
      from `generatedAt`
    - returns `{ status: 'drift', ageMs, changes: DriftChange[] }` otherwise, where each
      `DriftChange` is `{ kind: 'company' | 'relationship' | 'contact' | 'proposalLink' | 'pair' | 'skipped', direction: 'added' | 'removed' | 'changed', key: string, detail: string }`
    - a company present in `fresh` but not in `stored` yields one `added` change keyed on its
      company key
    - a pair suppressed in `fresh` but flagged in `stored` (an admin resolved it between the two
      runs) yields one `changed` change with a detail naming the verdict — this is the expected
      benign case and must be distinguishable from an unexpected one
    - `ageMs` is `fresh.generatedAt` minus `stored.generatedAt` in milliseconds
    - `computeDrift` is pure: it performs no I/O and no database access

    `formatDrift(result)` returns a multi-line human-readable string suitable for the CLI, with
    one line per change, prefixed `+` for added, `-` for removed and `~` for changed.
  </behavior>
  <action>
    Create `src/lib/reconcile/drift.ts` exporting `DriftChange`, `DriftResult`, `computeDrift`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| database → local filesystem | the report materializes live client names, partner display names and SIRENs into a plaintext file on an operator's machine |
| stored report → real-run authorization | a file on disk decides whether a bulk write proceeds; an attacker or an accident that swaps it changes what gets written |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-04-01 | Information Disclosure | report files committed to a public repository | mitigate | `.reconcile/` is added to `.gitignore` in Task 1 and asserted by an acceptance criterion; the report directory name is fixed in code as `REPORT_DIR` so no future caller can write elsewhere by accident |
| T-31-04-02 | Information Disclosure | credentials leaking into the report | mitigate | `databaseFingerprint` is a SHA-256 of hostname + database name only; the full `DATABASE_URL` is never read into the envelope, and a test asserts the report body contains no `DATABASE_URL` substring |
| T-31-04-03 | Information Disclosure | commission envelope (ADMIN-09) | mitigate | The report renders only `ReconciliationPlan` fields, and `ReconciliationPlan` has no `params_snapshot` / `computed` / commission field; a test asserts the rendered Markdown contains neither `params_snapshot` nor `commission` |
| T-31-04-04 | Tampering | a swapped or stale report authorizing writes against the wrong database | mitigate | `computeDrift` returns `fingerprint-mismatch` on a database change and `source-mismatch` on a source change, both before any change list is computed, so plan 07 can hard-abort on either |
| T-31-04-05 | Spoofing | a hand-edited `dry-run-latest.json` claiming a clean plan | accept | The file lives on the operator's own machine and the operator is the same person who runs the write. A signature would only defend against the operator defending against themselves. Recorded, not mitigated |
| T-31-04-06 | Denial of Service | unbounded report growth | accept | Archived reports accumulate in a git-ignored directory on an operator machine; the import is a one-time historical migration, run a handful of times |
| T-31-04-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs no packages — Markdown is rendered with template strings and hashing uses `node:crypto`. If a package appears necessary, stop and escalate |
</threat_model>
