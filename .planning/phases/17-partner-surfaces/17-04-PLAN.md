<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request → server component | searchParams (?q, ?archived, ?cursor) untrusted; userId from session (trusted) |
| Server component → buildListResponse | userId MUST come from session.user.id, NEVER from searchParams |
| Server component → FilterPillRow (client) | archived prop derived server-side from searchParams === '1' (bounded boolean) |
| FilterPillRow → router | URL navigation only — no API mutation; SSR re-render on click via <Link> |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-04-01 | Information disclosure (IDOR via query) | /proposals server component | mitigate | userId hardcoded from `session.user.id` (line in code); NEVER reads `?userId` from query; Test 7 enforces requireUser-before-buildListResponse order |
| T-17-04-02 | Information disclosure (Archivées window leak) | buildListResponse archived branch | mitigate | Plan 01 enforces the SQL filter `user_id=$userId AND ((status='active' AND derived expired) OR (status='deleted' AND deleted_at >= NOW() - INTERVAL '30 days'))`; this plan calls the helper with session-derived userId only |
| T-17-04-03 | Tampering (q param XSS) | SearchBar reused | accept | SearchBar reused verbatim from v1.1; ILIKE escaping handled by Drizzle parameterization; React auto-escapes the rendered query text in JSX |
| T-17-04-04 | Tampering (cursor manipulation) | cursorEncoded base64 | accept | Phase 8 cursor format is base64({createdAt,id}); decoded by buildListResponse; an attacker-supplied cursor that decodes to another user's createdAt+id still yields zero results because of the userId scope |
| T-17-04-05 | Open redirect (FilterPillRow href) | <Link> href literals | mitigate | hrefs are literal strings `/proposals` and `/proposals?archived=1` — no interpolation, no user input; cannot redirect off-site |
| T-17-04-06 | Information disclosure (commission leak via row projection) | ProposalsList consumer | mitigate | ProposalsList reuses ProposalRowDto from Plan 01 — commission stripped by projection; ADMIN-09 9-gate suite verifies trivially |
</threat_model>
