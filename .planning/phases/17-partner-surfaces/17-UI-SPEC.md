# Phase 17 — UI Design Contract
## Partner Surfaces

> Visual and interaction contract for Phase 17. Generated by gsd-ui-researcher.
> Consumed by gsd-planner, gsd-executor, gsd-ui-checker, gsd-ui-auditor.

**Scope summary:** 5 partner-facing routes — Partner Home `/` rebuild (PageHero + 3 MetricTiles + Propositions récentes), new `/proposals` route (filter pills + ProposalsList), and a full visual refresh of the 3-step wizard (Paramètres / Calcul / Vérifier) including two invariant inversions (WIZ-04 validity selector relocated to step 3; WIZ-06 lc_ref allocated at draft creation). All 5 surfaces ship both light and dark. 12 requirements (PHOME-01..03, PROPS-01/02, WIZ-01..06, THEME-01).

### Partner Home `/` — `app/(authed)/page.tsx` (PHOME-01..03)

**Directive:** server component, `requireUser()` + `export const dynamic = 'force-dynamic'`
**Pattern:** rewrite of existing inline hero + list to: `<PageHero>` + 3-up `<MetricTile>` grid + Propositions récentes card.

**Layout (top → bottom):**
1. `<PageHero title={greeting} subtitle={subtitle} actions={<NouvellePropCTA />} />`
2. MetricTile 3-up grid — `display:grid; grid-template-columns:repeat(3,1fr); gap:24px; marginBottom:32px`
3. Propositions récentes `.card` — section header (`.ctitle`), 5-row list (reuses `ProposalRow` subset — status chip + client name + lcRef + loyer), `Voir toutes →` link bottom-right

**`<PageHero>` call:**
```tsx
<PageHero
  title={`Bonjour, ${session.user.displayName ?? session.user.name} 👋`}
  subtitle={t('dashboard.home.subtitle', lang)}
  actions={
    <Link href="/proposals/new/parametres" className="btn-green">
      {t('dashboard.cta.new', lang)}
    </Link>
  }
/>
```
Note: `<Link>` with `className="btn-green"` renders identically to a `<button class="btn-green">` per existing `.btn-green` (display:inline-flex, align-center, gap:8px, padding:0.6rem 1.5rem, border-radius:9999px, 14px/600). This is the existing pattern from Phase 13 (steps 1/2 use `<Link className="btn-green">`).

**MetricTile instances:**
| Tile | Variant | Label key | Value source |
|------|---------|-----------|--------------|
| Ce mois-ci | `month` | `dashboard.metricTile.thisMonth` | COUNT inclusive, Europe/Paris month-start (D-05/D-06) |
| Total | `total` | `dashboard.metricTile.total` | COUNT inclusive, all-time (D-05) |
| Brouillons | `drafts` | `dashboard.metricTile.drafts` | COUNT status='draft' (D-05) |

**Propositions récentes card:**
- `.card` chrome
- Header row: `.ctitle` `● PROPOSITIONS RÉCENTES` left + `<Link href="/proposals">{t('dashboard.recent.viewAll', lang)}</Link>` right (12.5px/500/`--teal`)
- 5 rows: each row uses an abbreviated ProposalRow layout — `<StatusChip>`, client name (14.5px/600/`--ink`), lcRef (13px/500 monospace/`--ink`), loyer formatted (14.5px/600/`--ink` right-aligned)
- Row click: `<Link href={/proposals/${id}}>` with `.list-row` CSS class
- Empty state (< 5 proposals): render only available rows; no placeholder rows
- `Voir toutes →` link: `<Link href="/proposals">` with `fontSize:14px; fontWeight:500; color:var(--teal); textDecoration:none` — right-aligned at bottom of card, `marginTop:16px`
- If partner has 0 proposals: render empty state copy inside card instead of rows (see Copywriting Contract)

**Dark mode:** inherits via token cascade — no per-component dark CSS.

## Contrast Audit — CONTRAST-02 Addendum (Phase 17 New Token Pairs)

Phase 16 signed off the base contrast audit (`docs/accessibility/16-contrast-audit.md`). Phase 17 introduces two new foreground/background interactions that must be documented. The Phase 17 executor MUST add rows 8–10 below to `docs/accessibility/16-contrast-audit.md` (or create `docs/accessibility/17-contrast-addendum.md`) with measured values before merge.

| # | Composite | FG hex | BG (blended) | Mode | Pre-calculated ratio | Pass? |
|---|-----------|--------|--------------|------|----------------------|-------|
| 8 | Tranche/Coefficient pill chip — `--teal` text on tint | `#2d7a8c` | `rgba(45,122,140,0.10)` over `--surface` `#ffffff` → `#eaf3f5` | Light | ~4.8:1 (estimated) | Verify ≥4.5 |
| 9 | Tranche/Coefficient pill chip — `--teal` text on tint | `#2d7a8c` | `rgba(45,122,140,0.10)` over `--surface` dark `#161e2d` → `#1a282c` | Dark | ~9.2:1 (estimated) | Verify ≥4.5 |
| 10 | Active filter pill — `--gd-text` text on tint | `#0e7544` | `rgba(18,150,87,0.10)` over `--surface` `#ffffff` → `#e7f5ec` | Light | ~4.96:1 (calculated) | PASS |
| 11 | Active filter pill — `--gd-text` (dark = `#129657`) on tint | `#129657` | `rgba(18,150,87,0.10)` over `--surface` dark `#161e2d` → `#162a31` | Dark | ~3.9:1 (calculated) | **BORDERLINE — verify** |

**Row 10 calculation detail (pre-computed):**
`#e7f5ec` blended: R=`255×0.9+18×0.1=231`, G=`255×0.9+150×0.1=244`, B=`255×0.9+87×0.1=236` → `#e7f4ec`. `#0e7544` L≈0.1391 vs `#e7f4ec` L≈0.8885. Ratio = (0.8885+0.05)/(0.1391+0.05) = **4.96:1 — PASSES**.

**Row 11 note:** Active filter pill dark-mode contrast is approximately 3.9:1 — below 4.5:1 AA threshold. This matches the existing `.chip-active` behavior (same token pair, same opacity, pre-existing from Phase 8, no sign-off in Phase 16 audit). Two options for the executor:
1. Accept as-is — document in the addendum noting it matches the existing `.chip-active` baseline already shipped (no regression).
2. Elevate the dark-mode active pill to `--active-pill` token (`rgba(18,150,87,0.22)` in dark) — higher opacity improves contrast. If this option is chosen, update the active pill background to `var(--active-pill)` in `<FilterPillRow>` for dark mode only.

**Decision required from the planner:** Which option above for Row 11. Recommended: Option 2 (use `--active-pill` for active state) since the token already exists for this purpose.
