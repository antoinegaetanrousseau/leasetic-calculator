<interface_contract>
`scripts/_db-branch-guard.ts` exports:

```
export type TargetVerdict = 'ok-development' | 'ok-local-postgres' | 'warn-preview' | 'refuse-production' | 'refuse-unrecognised' | 'refuse-malformed';

export function classifyDatabaseTarget(url: string): { verdict: TargetVerdict; hostname: string; scope: string };

export function assertSafeDatabaseTarget(opts?: { cwd?: string; nodeEnv?: string; processEnv?: NodeJS.ProcessEnv; onRefuse?: (message: string) => never }): void;
```

- `classifyDatabaseTarget` is pure and exported for test access (the
  `__resolveTrustedOriginsForTests()` convention in `src/lib/auth/index.ts`). It derives the
  hostname with `new URL(url).hostname` — **never `URL.host`**, because `host` carries the port and
  an explicit `:5432` would slip a prefix match (bug_011, documented in
  `scripts/_neon-endpoints.list`). A URL that does not parse yields `refuse-malformed` with
  `hostname: ''`.
- Verdict mapping, derived from `NEON_ENDPOINTS`'s `branch` field, never from a second hardcoded
  table: `main` ⇒ `refuse-production`; `preview` ⇒ `warn-preview`; `development` ⇒
  `ok-development`; `localhost` or `127.0.0.1` ⇒ `ok-local-postgres`; anything else ⇒
  `refuse-unrecognised`. The last arm is the fail-safe direction established by
  `scripts/_neon-target.ts` — an endpoint we cannot prove is safe is treated as production.
- `assertSafeDatabaseTarget` defaults `cwd` to `process.cwd()`, `nodeEnv` to
  `process.env.NODE_ENV ?? 'development'`, `processEnv` to `process.env`, and `onRefuse` to a
  function that prints the message to stderr and calls `process.exit(1)`. The `onRefuse` injection
  point exists so tests can assert refusal without killing the vitest worker.
- **SKIP rule (load-bearing):** if `resolveDatabaseUrl(...).filesFound` is empty, the function
  returns immediately and silently. No env file on disk means a CI runner, a Vercel build, or the
  `MIGRATE PROD` GitHub Action — all of which legitimately point at production and must not be
  blocked.
- On a `warn-preview` verdict it writes one advisory line to stderr and returns. On any `refuse-*`
  verdict it calls `onRefuse` with a message containing the hostname and the `EnvResolution.source`
  filename, and nothing else.
</interface_contract>
