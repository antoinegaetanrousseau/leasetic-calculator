<interface_contract>
The file format this plan establishes is consumed by three plans downstream. It is fixed here and
must not be renegotiated in 39-03, 39-04 or 39-05.

**`scripts/_neon-endpoints.list`** — plain UTF-8 text, LF line endings.
- Lines whose first non-whitespace character is `#` are comments and are ignored.
- Blank/whitespace-only lines are ignored.
- Every other line is a record of exactly four `|`-separated fields, with NO spaces padding the
  separator: `prefix|hostname|branch|scope`
  - `prefix` — the endpoint id without the `-pooler...` suffix, used for `startsWith` matching.
  - `hostname` — the full pooled DNS name, used for exact-equality matching.
  - `branch` — exactly one of `main`, `preview`, `development`.
  - `scope` — human-readable label, e.g. `PRODUCTION (Neon branch \`main\`)`.
- Chosen over JSON deliberately: bash must read this without `jq` (not a declared dependency), and
  a per-record `while IFS='|' read -r` loop cannot mis-pair fields the way three independent
  `grep -o` passes over JSON keys can. A mis-pairing bug here is a misclassification bug, i.e. a
  fail-open.

**`scripts/_neon-endpoints.ts`** — exports:
- `interface NeonEndpointRecord { prefix: string; hostname: string; branch: 'main' | 'preview' | 'development'; scope: string }`
- `parseNeonEndpointList(contents: string): NeonEndpointRecord[]` — pure, exported for test access
  (mirroring the `__resolveTrustedOriginsForTests()` convention in `src/lib/auth/index.ts`).
- `NEON_ENDPOINTS: ReadonlyArray<NeonEndpointRecord>` — the parsed file contents.
Consumers derive their own severity from `branch`; the data file carries no per-consumer policy.
</interface_contract>
