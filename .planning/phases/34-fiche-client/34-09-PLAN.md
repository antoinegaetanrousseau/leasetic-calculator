<decision_record>
## The card is absent, not empty, when there is nothing to chase

The recent-proposals card renders an empty-state twin ("no proposals yet") because a partner with
zero proposals still needs to know the surface exists. "À relancer" is the opposite: an empty
follow-up list is *good news*, and a permanent "Rien à relancer" card is a permanent piece of
furniture reporting the absence of a problem.

**Chosen: render nothing when the list is empty.** No card, no header, no empty state. This also
makes the admin case fall out for free — an admin owns no relationships, gets an empty list, and
sees no card, with no role branch anywhere in the page (which would otherwise be a second surface
to secure).

`dashboard.relance.empty` was minted in plan 34-01 anyway; leave it unused rather than deleting it
(plan 34-01 owns `dictionaries.ts` and no later plan edits that file), and note in the SUMMARY that
it is reserved for a future "Relances" page.

## Row limit

`app/(authed)/page.tsx:43` sets the house convention: `recentList.rows.slice(0, 5)`. The follow-up
list applies the same limit, but **in SQL** via `listRelationshipsNeedingFollowUp(ownerId, 5)`
rather than by slicing in TypeScript — the query orders by a computed bucket and a coalesced date,
so slicing after the fact would be correct only by accident, and fetching an unbounded list to show
five is a home-page cost with no upside.
</decision_record>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session → query argument | the only legitimate source of an owner id on a multi-role page |
| role → rendered surface | a role branch would create two surfaces to secure instead of one |
| server-rendered props → client | rows that have crossed the owner scope once and must not be re-widened |
| server clock → rendered label | a derived value that must not depend on the client clock |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-09-01 | Information Disclosure | another partner's relationships appearing on a shared home page | mitigate | `listRelationshipsNeedingFollowUp` compiles `ownerId` into its WHERE (plan 34-05) and is called with `userId` from the session; test 1 asserts the argument equals the mocked session id exactly. Test 6 asserts an admin sees nothing. |
| T-34-09-02 | Elevation of Privilege | an owner id sourced from a search param, header or cookie | mitigate | The page accepts no `searchParams` for this query and passes `userId` literally; `grep -c "userId"` is asserted and test 1 checks the exact value. |
| T-34-09-03 | Spoofing | a role branch producing a different surface for admin than for partner | mitigate | `grep -c "requireAdmin"` and `grep -cE "role ===\|role !=="` are both asserted 0; the admin case falls out of owning no relationships. |
| T-34-09-04 | Information Disclosure | a cross-partner aggregate or count reaching the card | mitigate | The card renders only the rows it is given; test 6 (task 1) asserts a fixture "other partner" string never appears. No count, ranking or comparison is rendered (CRM-02, and Phase 33 D-12 restated for the board). |
| T-34-09-05 | Tampering | a client-clock-derived "overdue" label disagreeing with the server | mitigate | `nowMs` is computed on the server and passed as a prop; `grep -c "Date.now()"` in the component is asserted 0. |
| T-34-09-06 | Denial of Service | an unbounded follow-up query on the highest-traffic page | mitigate | The limit is applied in SQL (`listRelationshipsNeedingFollowUp(userId, 5)`), not by a TypeScript slice, and the query is served by `client_relationships_owner_id_next_action_at_idx` from plan 34-01. |
| T-34-09-07 | Information Disclosure | untranslated hardcoded strings shipping | mitigate | The component lives outside every vendored path, so ESLint's SHELL-06 hardcoded-JSX-text rule binds and `npm run lint:check` fails the build on any hardcoded string. |
| T-34-09-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependency. `git diff package.json package-lock.json` must be empty. |
