renders.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local script → database / blob storage | any local render path that reaches a real proposal row would hit the production Neon branch `.env.local` points at |
| rendered artefact → local filesystem | preview PDFs must not be committed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-08-01 | Tampering | a preview path that reads or writes production data | mitigate | `render-pdf-preview.ts` imports only `__pdf-fixtures__/fixtures.ts` and `renderProposalPdf`; it performs no `db()` call and no `storage()` call, and its header comment forbids extending it to read a proposal row |
| T-43-08-02 | Information disclosure | committing a rendered proposal into git | mitigate | `.preview/` is added to `.gitignore`; the fixtures contain only synthetic names and a `.example` email, but the directory is ignored regardless |
| T-43-08-03 | Information disclosure | commission visible to the human reviewer on the agent fixture | mitigate | Step 4 of the verification is an explicit human commission check on `agent-commission-free.pdf`, complementing the automated DOC-12 gates in plan 43-07 |
| T-43-08-04 | Repudiation | an approval that does not say what was checked | mitigate | Seven itemised checks (a–g) plus two named checks, each requiring an explicit answer recorded in the SUMMARY |
| T-43-SC | Tampering | npm/pip/cargo installs | mitigate | No install. `tsx` is already a dev dependency used by twelve existing scripts. Gate: `git diff --stat package-lock.json` empty at plan close |
</threat_model>
