<objective>
Land every FR/EN string the redesigned document renders, sourced verbatim from the two design files,
and dispose of the keys the redesign orphans.

Purpose: D-01 makes the design files authoritative for copy. Every card label, table row,
acceptance-block label and the full legal conditions paragraph differ between `Quote-FR-A.dc.html`
and `Quote-EN-A.dc.html` (DOC-10), and DOC-06 requires one deliberate deviation from both — the
validity period must interpolate the proposal's own `validityDays` rather than the design's
hardcoded "30 jours" / "30 days".

Output: ~32 new `pdf.*` FR/EN pairs, four existing pairs re-valued to the design's wording, five
orphaned keys ledgered (not deleted), three annotated, and new pinning tests.

**This plan deletes no dictionary key.** Per 43-01's phase-wide deletion rule, `DictKey` is
`keyof typeof dictionaries.fr`, so removing a key here would break the five `t()` calls
`document.tsx` still makes at this point in the wave order (`pdf.tagline` §138, `pdf.ref.label` §145,
`pdf.section.project` §170, `pdf.section.interests` §258, `pdf.footer.left` §312) — a compile error
for one to two waves, not a runtime no-op. Each orphan's deletion belongs to the plan that removes
its last consumer: 43-05 for the first three, 43-06 for the last two. This plan writes the ledger
that tells those plans what to remove.

This plan writes no rendering code. It is deliberately parallel to 43-02 and 43-04 — no shared files.

**Why wave 2 rather than wave 1:** `depends_on: [43-01]` because D-03 requires the DOC-03 amendment
in `REQUIREMENTS.md` to land before any plan implements DOC-03, and this plan's contact-card copy
does. There is no file overlap with 43-01 — the serialization is the requirement-text ordering only.
</objective>
