Thread the data the new layout needs into the render path, and land the single absence formatter
DOC-11's geometry guarantee depends on.

Purpose: nothing advisor-shaped reaches `document.tsx` today (D-12). The `VOTRE CONTACT` card needs

partner company telephone off the session, an `emDash` helper, and the four test files whose mocks
and fixtures must move in the same diff.

likeliest silent gap. It is in `files_modified` and in this plan's `<read_first>` for a reason: the
grown interface will surface it at compile time, and the acceptance criteria gate on both files.

**Why wave 2 rather than wave 1:** `depends_on: [43-01]` because D-03 requires the DOC-03 amendment
in `REQUIREMENTS.md` to land before any plan implements DOC-03, and threading the four advisor
columns into `ProposalDocumentProps` is that implementation. There is no file overlap with 43-01 —
the serialization is the requirement-text ordering only.

breadth is deliberate, not drift: D-12 makes the interface change atomic. Growing

routes that feed them, and the four test files whose mocks and fixtures type against the old shape.
Splitting them across plans would leave `npm run typecheck` red at a wave boundary — the exact gap
this phase's deletion sequencing exists to prevent. **Do not split this plan.** Every file here is a
compile-time consequence of the one interface edit in `document.tsx`.
