<objective>
Apply migration `0009_phase33_pipeline` to the Neon **development** branch through the gated
GitHub Actions workflow, and record the run.

Purpose: `npm run typecheck`, `npm run build` and every unit test in this phase derive their types
from `src/db/schema.ts`, **not** from the live database — so all of them pass whether or not the
migration ever landed. Nothing in wave 2 or wave 3 proves the columns exist. Plan 33-08's
integration test is the first thing that touches a real database, and it will fail confusingly if
this step was skipped. This plan exists so the apply is an explicit, dated, human-approved event
rather than an assumption.

Output: no source files. A SUMMARY recording the workflow run and the live-schema confirmation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| migration file → production database | DDL executed with elevated privileges |
| workflow_dispatch input → shell | operator-supplied `branch`/`confirm` values |
| local developer machine → shared Neon branch | an ad-hoc connection that would bypass the gated path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-02-01 | Tampering | migration reaching a database out of band | mitigate | The only sanctioned path is `db-migrate.yml`; `scripts/check-no-drizzle-push.sh` blocks the `push` alternative in CI, and this task's acceptance criteria require a workflow run URL as evidence rather than a local command transcript. |
| T-33-02-02 | Elevation of Privilege | an unintended apply against the `main` (production) Neon branch | mitigate | Task explicitly targets `development`; the workflow independently requires a typed `MIGRATE PROD` confirmation plus a GitHub Environment reviewer for `main`. An acceptance criterion asserts no `main` run occurred. |
| T-33-02-03 | Tampering | command injection via `workflow_dispatch` inputs | transfer | Already mitigated in the workflow itself: `branch` is a constrained `type: choice` and `confirm` flows through the `CONFIRM_INPUT` env var before any shell evaluation (Phase 20-02 security note, `db-migrate.yml:20-24,70-76`). No change is made here. |
| T-33-02-04 | Repudiation | no record of when the schema changed | mitigate | The workflow run URL, target branch and live-schema query output are recorded in the SUMMARY, giving a dated, attributable trail. |
| T-33-02-05 | Information Disclosure | a connection string pasted into a log or artifact while verifying steps 5-6 | mitigate | Verification queries are run by the operator locally against their own environment; the SUMMARY records the query *results* (four column names, two trigger names), never the connection string. |
| T-33-02-SC | Tampering | npm/pip/cargo installs | mitigate | No dependency change; this plan modifies no file. |

</threat_model>
