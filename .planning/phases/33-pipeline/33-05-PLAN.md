<decision_record>
## The reserved lane's own visual muting ships here; the refusal toast ships in 33-07

33-UI-SPEC.md § "Reserved-lane drop refusal" specifies three always-active layers. Two of them are
pure rendering and belong with the header component: layer 1 (always-on muting — `bg-muted/40`,
`BanIcon`, "Réservé" badge instead of a count) and layer 2 (the drag-in-progress
`ring-destructive/40` + `cursor-not-allowed` CSS rule). Layer 3 — the refusal toast raised from
`onMove` — is inseparable from the drag handler and ships in plan 33-07 with the board.

Recorded because plan 33-01's threat model attributes "renders the lanes as refusing drops" to this
plan: it is true for the visual layers, and 33-07 completes the set. A reviewer checking 33-05 alone
should not expect the toast here.

## `Perdu` collapses via `Collapsible`, not `Accordion`

33-PATTERNS.md flags that it is unverified whether `src/components/ui/accordion.tsx` exists. It does
NOT — `ls src/components/ui/` shows `collapsible.tsx` and no `accordion.tsx`. Both the `Perdu` lane
disclosure and plan 33-07's mobile stage sections therefore compose shadcn `Collapsible` /
`CollapsibleTrigger` / `CollapsibleContent`. Do not run `shadcn add accordion` — a new registry pull
is out of this contract's Registry Safety scope and `Collapsible` covers both cases.
</decision_record>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| query row → rendered card | data that has already crossed the owner scope; a render bug cannot re-open it, but a wrong id in a link can |
| relationship id vs company id in the card link | the phase's sharpest IDOR-shaped surface, inherited from `/clients/[id]` |
| nav entry visibility → role | an entry rendered for a role the route refuses |
| CSS rule → global stylesheet | an over-broad selector affecting unrelated surfaces |
