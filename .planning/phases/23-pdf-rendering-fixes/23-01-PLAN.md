<objective>
Fix PDF-01: numeric/typography glyph overlap on the generated proposal PDF.

The root cause is confirmed: `src/lib/i18n/format.ts` `formatCurrency()` / `formatNumber()`
call `new Intl.NumberFormat('fr-FR', …)`, and modern ICU emits the French grouping
separator and the space before the EUR symbol as codepoint U+202F (NARROW NO-BREAK SPACE),
sometimes U+00A0 (NO-BREAK SPACE). The embedded Plus Jakarta Sans TTF subset has no glyph
for U+202F, so @react-pdf/renderer (PDFKit/fontkit) renders `.notdef` / overlapping
characters — most visible on the loyer feature card, the montant HT row, and the
coefficient % row.

Purpose: Make all numeric values legible in the PDF for ALL partner types, without
changing web rendering (browsers HAVE the U+202F glyph, so the web is fine and must NOT
change). The fix is therefore PDF-scoped — a sanitizer used only by the PDF layer.

Output: A `src/lib/pdf/sanitize-number.ts` helper + reproduction test, with every
formatted numeric string in `document.tsx` routed through it before reaching a `<Text>`.

NOTE TO EXECUTOR: this plan deliberately refers to the problem characters by their
codepoint names (U+202F, U+00A0, U+0020) and never embeds the literal invisible glyphs in
prose. In the source + tests, reference them via escape sequences (``, ``,
` `) so the files stay greppable and diff-clean.
</objective>
