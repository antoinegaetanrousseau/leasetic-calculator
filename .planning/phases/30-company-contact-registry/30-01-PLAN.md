1. **Prepend the normalization function.** `companies.name_normalized` is
   `GENERATED ALWAYS AS (leasetic_normalize_company_name(name)) STORED`, so the function must
   exist before `CREATE TABLE "companies"`. Add as the first statement (followed by
   `--> statement-breakpoint`):
   `CREATE OR REPLACE FUNCTION leasetic_normalize_company_name(input text) RETURNS text LANGUAGE sql IMMUTABLE STRICT PARALLEL SAFE AS $$ ... $$;`
   The body must be pure SQL — `IMMUTABLE` is mandatory for a stored generated column, which rules
   out the `unaccent` extension (it is only STABLE). Implement the CRM-01 rules in this order:
   (a) `lower()`; (b) strip accents with `translate()` over the literal pairs
   `àáâãäåçèéêëìíîïñòóôõöùúûüýÿ` → `aaaaaaceeeeiiiinooooouuuuyy`; (c) replace every run of
   non-`[a-z0-9]` characters with a single space via `regexp_replace(..., '[^a-z0-9]+', ' ', 'g')`;
   (d) remove standalone French legal-form tokens by wrapping the string in leading/trailing
   spaces and running `regexp_replace(..., ' (sarl|sasu|sas|sa|eurl|sci|snc|scop) ', ' ', 'g')`
   twice so adjacent forms both match; (e) collapse whitespace again and `btrim()`.
   Longer tokens must be listed before their prefixes in the alternation (`sasu` before `sas`
   before `sa`) or Postgres will match the shorter one first.
2. **Order the role CHECK before the backfill.** Confirm the generated statements drop
   `users_role_check` and re-add it with `IN ('partner','admin','sales')`. Then append, AFTER
   that re-add: `UPDATE "users" SET "role" = 'sales' WHERE "partner_type" = 'Commercial' AND "role" = 'partner';`
   The `AND "role" = 'partner'` guard is load-bearing — it must not demote an admin who happens
   to carry `partner_type = 'Commercial'` (ROLE-03).
3. **Confirm the proposals ALTER is additive only.** The proposals section must contain exactly
   one `ADD COLUMN "client_relationship_id"`, one FK constraint and one CREATE INDEX. If
   drizzle-kit emitted any statement touching `inputs`, `params_snapshot`, `computed` or an
   existing CHECK on `proposals`, delete it — CRM-05 forbids it.
4. **Separate every statement with `--> statement-breakpoint`.**

Apply locally against the Neon `development` branch: run `npm run check:local-db-branch` first
