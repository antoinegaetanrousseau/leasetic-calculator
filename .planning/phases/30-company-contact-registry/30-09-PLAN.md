<objective>
Close CRM-05: wire the proposal wizard to the registry so a proposal started from a client record
carries `proposals.client_relationship_id`, without touching the `inputs` JSONB snapshot. Then
verify the whole phase end to end, including the cross-tenant isolation that is its reason to exist.

Purpose: CRM-06's promise ("every proposal I made for this client, on one page") is only true if
new proposals actually get linked. And CRM-05's constraint — the FK must not disturb the frozen
snapshot — is the invariant that keeps every previously generated PDF reproducible.

Output: an optional `clientRelationshipId` on draft creation, ownership-validated wizard entry
with graceful degradation, a snapshot-integrity regression test, and a human verification pass
over the phase.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `?clientRelationshipId=` search param → draft creation | an id supplied by the caller, possibly copied from someone else |
| draft finalization → `proposals.inputs` | the immutable snapshot backing every generated PDF |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-09-01 | Information Disclosure | `?clientRelationshipId=` as an existence oracle | mitigate | The param is validated through `getClientRelationshipForOwner(id, session.user.id)`, and a `null` result is handled identically to a malformed value — the wizard proceeds unlinked with no error, no 404 and no toast, so an owned and a non-owned id are indistinguishable from the caller's side (CRM-02) |
| T-30-09-02 | Elevation of Privilege | linking a proposal to another partner's relationship | mitigate | The FK is written only from the validated mint path; a grep gate asserts there is no second write path to `client_relationship_id` |
| T-30-09-03 | Tampering | snapshot integrity | mitigate | `clientRelationshipId` is added to `CreateDraftArgs` only; `updateDraft` still sets `inputs` alone and `finalizeDraft`'s set-object is asserted by test to contain no `inputs` key, plus an end-to-end deep-equal assertion in `finalize-wizard.test.ts` (CRM-05) |
| T-30-09-04 | Information Disclosure | prefilled client data leaking across partners | mitigate | Prefill sources come exclusively from `getClientRelationshipForOwner` and `listContactsForRelationship`, both owner-scoped; if validation dropped the id, no prefill happens at all |
| T-30-09-05 | Denial of Service | a stale link blocking a partner from quoting | mitigate | Graceful degradation is the specified behavior — a bad param never produces an error page |
| T-30-09-06 | Information Disclosure | commission envelope (ADMIN-09) | mitigate | No change to `params_snapshot` computation or projection; the wizard's existing step-1 invariant (no partner-only parameter identifier on step 1) is untouched |
| T-30-09-SC | Tampering | npm/pip/cargo installs | mitigate | No package install occurs in this plan |
</threat_model>
