<objective>
Lay the data-layer and type contracts the rest of Phase 44 is built on: the audit action that
serves as the idempotence marker (D-06), the anti-join query that defines the in-scope row set
(D-03), and the `src/lib/backfill/types.ts` contract file that plans 02, 03 and 04 all import so
none of them has to go looking for shapes in the codebase.

Idempotence is an `audit_log` row per migrated proposal, never a `pdf_sha256` comparison — the raw
buffer hash is not stable across renders (`src/lib/pdf/render.ts:19`), so hash comparison would
report every row as changed.

Output: one new union member, two new query functions, one new contract module, one new test file.
No schema migration is created or applied in this plan or anywhere in Phase 44 (D-06 chose the
audit-log marker precisely so no migration is needed).

| Boundary | Description |
|----------|-------------|
| stored jsonb → typed contract | `proposals.inputs` / `proposals.computed` are `Record<string, unknown>` written by code as old as Phase 8; nothing guarantees they satisfy today's schemas. The boundary is crossed in plan 02, but the contract that admits `unknown` is declared here. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-01 | Information disclosure | `BackfillReportRow` in `src/lib/backfill/types.ts` | mitigate | The report row type is a closed, explicit field list that excludes `inputs`, `computed`, `paramsSnapshot`, every figure, and the blob key; the type carries the prohibition in its own docstring so plan 03 cannot widen it by accident. |
| T-44-02 | Information disclosure | `'proposal.pdf_backfill'` audit payload | mitigate | Payload restricted by the union's section comment to `language` + `pdfSizeBytes`; ADMIN-09 holds by construction because `computed` is copied verbatim and never derived from `global_params` at backfill time. |

| T-44-04 | Repudiation | operator-run bulk mutation | mitigate | The audit row is written per migrated proposal with `actorId: null` and a `targetId`, so `audit_log_target_type_target_id_created_at_idx` makes "was this document re-rendered, and when" answerable per proposal. |
