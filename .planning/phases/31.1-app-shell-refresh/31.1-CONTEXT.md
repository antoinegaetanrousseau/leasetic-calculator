# Phase 31.1: App Shell Refresh - Context

**Gathered:** 2026-09-02
**Status:** Ready for planning

<domain>
## Phase Boundary

The application shell — sidebar, header chrome, brand lockup, and the radius token scale —
converges on **Colibris** (`https://colibris-eosin.vercel.app`), a sibling product built on the
same ReUI `base-maia` design system. The two apps serve the same teams and are meant to read as
belonging to one group despite being separate brands, so this phase is about **structural
alignment**, not a redesign.

Presentation only. No schema, no data, no new capabilities.

**Not in this phase:** search (`⌘K`), notifications, and the entity switcher visible in Colibris's
own shell. Those are capabilities, not chrome, and each would be its own phase.

</domain>

<decisions>
## Implementation Decisions

### Radius — the scale, not just the corners

- **D-01:** Container surfaces render at **16px**, via a single named container-radius token,
  back-applied to Phase 30's `.card` and Phase 31's pair-review card + its two dialogs. This
  closes **OPEN-A** in `UI-CONVENTIONS.md`, which was explicitly parked for this phase.
- **D-02:** Replace the `--radius × multiplier` block (`app/globals.css:481-487`, ×0.6 → ×2.6)
  with **explicit per-step values matching Colibris: 12 / 16 / 24 / 32 / 40px**. This is the
  mechanism, and it is the whole point: Leasétic's scale derives seven steps from one token, so
  raising the base to chase a "large radius" inflated every step at once and turned every `Input`
  into a pill — the documented incident at `app/globals.css:66-74` that produced **UIC-04**.
  Colibris avoids it by declaring each step, letting containers be generous while controls stay
  at 8px. Note this **supersedes UIC-04's multiplier clause**; UIC-04 must be revised, not
  silently violated.
- **D-03:** Controls — `Input`, `Button`, `Select`, `Badge`, radio items — keep their current
  **8px**. Measured: Colibris's controls are also 8px. Nothing about controls changes.

**Measured before deciding, and it inverted the premise.** Colibris's cards render at **16px**,
which is *smaller* than Phase 31's 24px literal and within 2px of Phase 30's 18px. The two
products were already close on corners; what actually differs is the scale architecture. "Match
Colibris" therefore means Phase 31's 24px moves **down**, not Phase 30's 18px moving up.

### Header

- **D-04:** The breadcrumb trail **replaces** `TopbarTitle` rather than joining it. Colibris's
  header carries navigation context only; the page title lives in the content area, which is
  where Leasétic's `PageHero` already renders it — so this mostly removes duplication.
- **D-05:** Header layout is toggle + breadcrumb on the left, ADMIN badge on the right.
- **D-06:** The trail is derived from `getRouteMeta`, rendered in the viewer's language, with the
  current page as non-link text.

### Sidebar and the collapse control

- **D-07:** The collapse control **moves into the header**. Leasétic already has the right
  component — `<SidebarTrigger className="-ml-1 md:hidden" />` in `Topbar.tsx` — it is simply
  hidden above the `md` breakpoint. Unhide it, give it an FR/EN label, and delete the in-sidebar
  chevron. Colibris does exactly this: a labelled 32×32 "Toggle sidebar" button in the header.
- **D-08:** This is also the fix for the collapsed sidebar looking wrong. The current collapsed
  header switches to `flex-col` and stacks a 28px logo mark **above** the chevron; with the
  chevron gone there is nothing to stack, and the rail holds only the mark and the nav icons.
  The two directives are one change.
- **D-09:** **The collapsed mark must be centred on the nav icon column** — and here Leasétic
  should be *better than* Colibris, not merely equivalent. Measured on Colibris: rail 68px wide,
  nav icons centred at **33.5px** (dead centre), logo mark centred at **26px** — about **8px
  left**. Copy the structure (a 32×32 badge at 9px radius holding an 18×18 glyph), fix the
  centring.
- **D-10:** Expanded brand lockup drops from 190px to **~120px**. Colibris is 118px in a 252px
  sidebar (47% of width); Leasétic is currently 190px in 260px (73%). Matching the *proportion*
  is what makes them read as siblings. This is −37%, beyond the −26% originally asked for, but it
  is the number that actually matches — and it is close to the 130px the v10 prototype used
  before the lockup grew.
- **D-11:** Sidebar **252px** expanded, **68px** collapsed (from 260 / 72). Both are single-value
  changes in `Shell.tsx`'s inline `style` — which is already the correct place: the comment there
  records that setting them via `className` is a latent bug, because `SidebarProvider` spreads
  its own inline style and outranks an arbitrary-property class. The vendored `app-shell-1` block
  has that bug; do not copy it.
- **D-12:** Keep the **single nav group**. Colibris sections its nav (`PLATFORM`, `ENTITIES`), but
  Leasétic's nav is 5–7 flat items — too few to section, and the item set and order were
  deliberately settled by Phase 18 (D-27) and widened by Phase 30. Adopt only Colibris's eyebrow
  *styling*: **11px, uppercase, 0.55px letter-spacing**.

### Dark mode

- **D-13:** Match Colibris's dark palette. **The exact token values are to be sampled from the
  live app during research** — they are not recorded here.
  - Colibris's dark mode is real (operator-confirmed by screenshot) but is **not discoverable by
    scanning CSS**: the app has ~438 inline-styled elements against 2 stylesheets / 66 rules, so
    the theme is JS state applied inline. A `prefers-color-scheme` emulation plus reload does not
    trigger it, and no toggle was findable via `aria-label`, menu probing, or `localStorage`.
    **The researcher must ask the operator how to switch Colibris into dark mode before
    attempting to sample it.**
  - Sample at minimum: page background, elevated surface (cards), border, muted text, primary
    text, and how the teal accent shifts between themes.
  - This decision **expands the phase beyond its six ROADMAP success criteria**, which are all
    layout/token and say nothing about colour. It also reopens **UIC-03**, and `globals.css:20-22`
    records that a previous Figma-derived palette was deliberately reverted to ReUI defaults.
    **The ROADMAP entry for Phase 31.1 should gain a seventh criterion covering dark-mode
    alignment**, and UIC-03 must be revised rather than quietly contradicted.

### Claude's Discretion

- The container-radius token's **name**.
- Whether the explicit radius scale keeps the `--radius-*` naming or introduces new names, and how
  `--radius` itself is retained or retired for callers that still read it.
- Breadcrumb segment labels and how deep the trail goes on each route — as long as it derives from
  `getRouteMeta` and honours FR/EN.
- Whether `TopbarTitle` is deleted or kept as an unused export during migration.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `SidebarTrigger` — already imported in `Topbar.tsx`, just `md:hidden`. D-07 is mostly deleting a
  class and adding a translated label, not building a control.
- `breadcrumb.tsx` — the shadcn primitive is installed and proven on `aide/commencer-ici` and
  `partners/new`.
- `getRouteMeta` — already maps pathname → `{ activeNav, title }` for both partner and admin
  trees, including the `adminSegment` case. The breadcrumb trail should extend this rather than
  introduce a parallel route table.

### Established Patterns
- Sidebar collapse state is the shadcn primitive's own `collapsible="icon"` mode, persisted to the
  `sidebar_state` cookie and read server-side in `Shell.tsx` to seed `defaultOpen`. This removed a
  documented one-frame layout shift; do not reintroduce client-side collapse state.
- `Shell.tsx` is a server component; `AppSidebar.tsx` is `'use client'`. Admin hrefs are resolved
  server-side and forwarded, because the client component cannot read `process.env`.

### Integration Points
- Every authenticated page renders inside `Shell` → `SidebarInset` → capped `<main>` (UIC-09).
  D-04's breadcrumb sits in the header above that `<main>`, so it applies app-wide in one edit.
- The container-radius token change (D-01) touches every surface Phases 28/30/31 shipped. It is a
  token edit plus a back-application sweep, not a per-surface redesign.
- `--topbar-h` is read by the proposal detail page's sticky offset
  (`top: calc(var(--topbar-h) + 24px)`). If the header height changes to match Colibris's 52px,
  that offset follows automatically — but only if the change goes through the variable.

</code_context>

<specifics>
## Specific Ideas

- The motivation is explicit and worth carrying into planning: **the two apps serve the same teams
  and are meant to belong to one group**, though they are technically separate brands. Colibris's
  own sidebar lists `Leasetic France`, `Colibris SAS`, `Leasetic Iberia`, `Leasetic Benelux`,
  `Leasetic DACH` under a `Leasetic Group` breadcrumb. Alignment is a product requirement, not a
  taste preference.
- What the operator asked for was **structure**, not palette — with dark mode added afterwards as
  a separate ask (D-13).
- The collapsed-sidebar observation was specific: do the equivalent of Colibris, *but place the
  logo mark better*. Measurement confirmed Colibris is 8px off its own centre line. D-09 exists
  because of that observation.

</specifics>

<deferred>
## Deferred Ideas

- **Search (`⌘K`) and notifications** — Colibris's header carries both. They are capabilities, not
  shell chrome, and each deserves its own phase. Explicitly out of scope here.
- **Entity / workspace switcher** — Colibris's sidebar has a workspace menu and an `ENTITIES`
  section listing group companies. Leasétic has no equivalent concept; introducing one is a
  product decision, not a shell refresh.
- **Sectioned navigation** — revisit if the nav grows past ~8 items (D-12).
- **Plus Jakarta Sans** — the v10 prototype used it; the app is on Inter, and so is Colibris. No
  action, recorded so it is not re-raised.
- **`OPEN-B` in UI-CONVENTIONS.md** — `D-B` has no origin record. Untouched by this phase.

</deferred>
