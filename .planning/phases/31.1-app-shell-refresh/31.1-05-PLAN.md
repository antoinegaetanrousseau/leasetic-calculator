Apply D-13's dark palette to the four shell-surface token roles Colibris was actually sampled
for, inside the existing `html[data-theme="dark"]` block — value edits only, no new selector, no
new mechanism.

## The gaps are the contract — do not close them by guessing

`31.1-UI-SPEC.md` § "Unsampled — explicit gaps" lists three surfaces with no measurement:
dialog/popover elevation, input fill vs border, and sidebar hover/active in dark. **Inventing a
plausible hex for any of them would violate criterion 7 while appearing to satisfy it.** This
plan therefore leaves `--popover`, `--popover-foreground`, `--input`, `--secondary`, `--accent`,
`--sidebar-accent` and `--card-foreground` at their current values and records the three gaps as
a named follow-up in the SUMMARY. Plan 31.1-07's acceptance checkpoint puts the decision
(second screenshot, or accept-as-is) in front of the operator.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `theme` cookie → inline `<head>` script → `data-theme` attribute → which token block applies | A client-controllable cookie value selects a stylesheet branch on every page load. |
| Dark token values → the PDF/print surface | A token change can silently alter a document that gets sent to customers. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31.1-05-01 | Tampering | A dark-token edit leaking into the PDF surface, shipping a dark-background proposal to a customer | mitigate | The `[data-pdf-surface]` override is a separate rule with `!important`, untouched by this plan; `tests/dark-palette.test.ts` assertion 1 fails if it is removed or weakened |
| T-31.1-05-02 | Tampering | `theme` cookie value injected into the `data-theme` attribute by the no-flash script | accept | Pre-existing mechanism, unchanged by this plan (assertions 2-3 pin it). The attribute value only selects a CSS branch; an unrecognised value simply matches no block and falls back to light |
| T-31.1-05-03 | Repudiation | A future reader unable to tell a measured value from a guessed one | mitigate | Every changed value carries an inline provenance comment naming the source, date and confidence; assertion 5 pins the three unmeasured tokens so filling them requires a deliberate test edit |
| T-31.1-05-04 | Information Disclosure | Reduced contrast making sensitive on-screen content harder to read is a usability, not a disclosure, risk; conversely a too-low `--border` alpha could visually merge an admin-only panel with the page | accept | `--border` moves 10% → 8% alpha only; the operator acceptance checkpoint in Plan 31.1-07 includes a dark-mode read of an admin surface |
| T-31.1-05-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install in this plan |
</threat_model>
