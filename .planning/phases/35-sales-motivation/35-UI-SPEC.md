## Scope Boundary (read first)

### In scope — one surface

**One `Card`, three parts, on the home page (`app/(authed)/page.tsx`), below `<RelanceCard>`**
(D-04, D-17, D-18):

1. **Streak** — a sentence stating the current weekly streak and its break condition, always
   (D-02, D-12).
2. **This week's movements** — the specific deals that moved this week (D-09, D-10).
3. **Badge ladder** — three tiered ladders (clients / wins / consistency), all nine rungs always
   readable (D-06, GAME-03).

Plus one permanent, quiet disclosure line (operator instruction, 2026-09-04 — see § Copywriting
"Under-report disclosure") stating that only client-linked proposals are tracked.

### Explicitly out of scope for this document

| Item | Why it's not here |
|---|---|
| Any leaderboard, ranking, peer benchmark, or team aggregate | GAME-04 / D-15's permanent constraint — structurally unbuildable per CRM-02. Not merely undesigned; must never be added. |
| A toast, badge-earned notification, or "new since last visit" marker | D-08 — a badge is discovered on the page, nothing pushes it. |
| An opt-out, dismiss control, or stored preference | D-16 — no migration, no per-user state. |
| Any change to `/pipeline`'s board or `/clients/[id]` | D-20 — home page only; the board keeps exactly its existing two motivating elements (conversion rate, stage counts). |
| The Accueil/navigation redesign, Contrats, Rapports, "Encours total", ⌘K search | Deferred — `35-CONTEXT.md` § Deferred Ideas. |
| A migration or new column | D-23 — everything here is derived from `relationship_events` at read time. If a plan concludes otherwise, that reopens a locked decision and must be flagged, not built. |

## Visual Hierarchy

**The streak sentence is the entry point; the badge ladder is the least urgent read.** Stated
explicitly because all three parts share one `Card` at equal visual weight by default (D-18: "one
heading, one empty state") and nothing else forces a reading order.

Reading order, in priority:

1. **Streak sentence** — states where the partner stands and what is at stake this week (D-12).
   The only text on this card that carries any weight (`font-semibold` on the number+unit
   fragment only — see § Typography). This is deliberately the *same* visual weight `RelanceCard`
   gives its own overdue rows (`font-semibold`, never a color pop), not louder.
2. **This week's movements** — the evidence for the streak sentence immediately above it (D-10:
   "the list visibly explains why the streak stands"). Same row treatment as `RelanceCard`.
3. **Badge ladder** — a standing reference, not news. Renders last, in the smallest text size on
   the card, because GAME-03 requires it to be *readable*, not that it compete for attention.
4. **Under-report disclosure** — smallest, quietest text on the card, permanently present at the
   bottom (see § Copywriting).

**Consequence for the executor:** no part of this card may render larger or more saturated than
`RelanceCard`'s own rows. If a later request asks to "make the streak pop," that is a D-19
violation, not a styling preference — escalate rather than adding color or size.

## Color

Per [`UIC-03`](../../codebase/UI-CONVENTIONS.md) — same tokens, same 60/30/10 discipline, same
exhaustive per-surface reserve list.

| Role | Token | Usage on this surface |
|------|-------|-------|
| Dominant (60%) | `--background` | Page background |
| Secondary (30%) | `--card` | The one `Card` this phase renders |
| Accent (10%) | `--primary` | **None on this surface — see below.** |
| Feedback (not accent) | `--muted-foreground` / `--foreground` | Every text node on this card |

**Accent reserved for: nothing. This card introduces zero new brand-accent usage.**

This is a **stricter** budget than the page's own precedent — `MetricTile`'s `variant="total"`
already renders `text-primary` for a metric value one section above this card — and the stricter
budget is deliberate, not an oversight: D-19 says brand green is reserved for "where it **already
signals action**," and nothing on this card is an action. The streak number, the movement rows,
and the badge ladder are all informational. Rendering any of them in `--primary` would visually
compete with the page's one real action (`PageHero`'s "Nouvelle proposition" button) and read as
a second, undeserved call-to-action — the exact "two loud cards on one page and neither wins"
outcome D-19 names.

**Verified not to render accent here:** no `Button`, no `Link` with `text-primary`, no `Badge`
component (the earned-rung marker is a bare `CheckCircleIcon` in `text-foreground`, not a colored
badge chip). Movement rows ARE links to `/clients/[id]` (per § Copywriting "Momentum row
interaction") but render in `text-foreground`/`text-muted-foreground` exactly like `RelanceCard`'s
own rows — `RelanceCard` does not use `text-primary` for its row links either, so this is
consistent with the established sibling pattern, not a new exception.

**A backwards move or a move to Perdu (D-11) renders in the identical color to a forward
move — no `--destructive`, no muted-red, no down-arrow glyph.** This is the one place a checker
might expect a feedback color and must not find one: D-11 is explicit that this must carry
**no penalty framing**, and a destructive-family color is penalty framing.

## Copywriting Contract

| Element | FR | EN |
|---|---|---|
| Card eyebrow title | **"VOTRE PROGRESSION"** | **"YOUR PROGRESS"** |
| Streak — active (n≥1) | **"{n} semaine(s). Un dossier doit avancer d'ici dimanche."** | **"{n} week(s). A deal must advance by Sunday."** |
| Streak — zero state (D-13/D-14 combined, one paragraph per D-18) | **"Pas encore de série. Faites avancer un dossier cette semaine pour démarrer une série."** | **"No streak yet. Advance a deal this week to start one."** |
| Zero-state credibility line (D-14, dynamic month/year) | **"Activité suivie depuis {mois} {année}."** e.g. "Activité suivie depuis septembre 2026." | **"Activity tracked since {month} {year}."** |
| Movements — section label | **"Cette semaine"** | **"This week"** |
| Movement row — stage advance | **"{companyName} → {stageLabel}, {jour}"** | **"{companyName} → {stageLabel}, {day}"** |
| Movement row — proposal finalized | **"{companyName} — proposition envoyée, {jour}"** | **"{companyName} — proposal sent, {day}"** |
| Movement row — backwards move / Perdu (D-11, no penalty framing, same styling as any other row) | **"{companyName} → {stageLabel}, {jour}"** — identical shape to a forward move, never a distinct sentence, never a qualifier like "reculé" | **"{companyName} → {stageLabel}, {day}"** |
| Movements — empty this week (partner HAS history, just a quiet week) | **"Aucun mouvement cette semaine."** | **"No movement this week."** |
| Movements — truncation (>5 in the window) | **"+ {n} autres mouvements cette semaine"** (plain text, not a link — no page exists to link to) | **"+ {n} more this week"** |
| Badge axis — Clients | **"CLIENTS"** | **"CLIENTS"** |
| Badge axis — Wins | **"VICTOIRES"** | **"WINS"** |
| Badge axis — Consistency | **"RÉGULARITÉ"** | **"CONSISTENCY"** |
| Badge tier names | **"Bronze" / "Argent" / "Or"** | **"Bronze" / "Silver" / "Gold"** |
| Badge tier entry format | **"{Tier} ({n} client(s))"** / **"{Tier} ({n} victoire(s))"** / **"{Tier} ({n} semaine(s))"** | **"{Tier} ({n} client(s))"** / **"{Tier} ({n} win(s))"** / **"{Tier} ({n} week(s))"** |
| Under-report disclosure (operator instruction, permanent, all states) | **"Seules les propositions démarrées depuis une fiche client sont suivies ici."** | **"Only proposals started from a client page are tracked here."** |

**The "(s)" pluralization convention above is not invented for this phase** — it is the identical
shorthand `33-UI-SPEC.md` already shipped in production copy ("{won} gagnée(s) sur {total}
proposition(s)"), reused here for consistency rather than introducing real plural-rule branching
for a house style this small.

**Primary CTA:** N/A. This card is informational, not actionable — GAME-05 requires that ignoring
it costs nothing, which argues against giving it a CTA that competes with `PageHero`'s "Nouvelle
proposition". The closest analog is the movement row itself acting as a full-row link to
`/clients/{relationshipId}` — identical interaction to `RelanceCard`'s rows, no separate "voir"
label, no `Badge`/`Link` accent color (see § Color).

**Error state:** N/A — no bespoke error copy. A failed query surfaces via the route's existing
`app/error.tsx` boundary, the same house convention `RelanceCard` and the recent-proposals list
already rely on (neither has bespoke error UI of its own).

**Destructive confirmation:** N/A — no destructive action exists in this phase (D-16: no opt-out,
no dismiss control to confirm).

**Deliberately NOT written:** any sentence that varies its tone based on whether the partner is
"doing well" or "doing badly" (D-12's whole point — the break condition line is worded
identically in a good week and a bad one); any wording that mentions another partner, a rank, a
percentile, an average, or "compared to" anything (GAME-04, absolute).

## Access & Non-Leakage Contract (read before implementing anything below)

1. **Own-book only, always (D-21, CRM-02).** Every query this phase adds compiles `ownerId`
   into the same WHERE clause as the data lookup — the identical discipline
   `listRelationshipsNeedingFollowUp` and `listRelationshipEvents` already apply. No function may
   accept an "all owners" flag or a pre-checked boolean.
2. **Hidden entirely for admins, before any query runs (D-15).** This is stricter than
   `RelanceCard`'s pattern: `RelanceCard` queries first and renders `null` on an empty result,
   which is fine for a chase list (an admin's empty follow-up list IS the correct answer). It is
   **not** fine here, because a partner with genuinely zero history sees the populated zero-state
   ladder (D-13/D-14) — so "empty result" and "admin" must not collapse into the same rendering
   path, or an admin would see the zero-state invitation copy, which is itself a GAME-04-adjacent
   tell ("this feature exists and would apply to you if you held relationships"). The page checks
   the session's role **before** calling any momentum/streak/badge query and skips the card
   entirely for an admin — no query, no component render, no DOM node.
3. **No cross-partner inference surface (GAME-04, `30-SECURITY.md`'s inference standard).** No
   count, total, percentage, or wording on this card may be derived from, or hint at, any other
   partner's data. Badge tier thresholds are fixed constants shared by the codebase (not
   per-partner data), so displaying them is not a leak — the leak risk this contract guards
   against is a partner's OWN numbers ever being contextualized against anyone else's ("you're
   in the top X%", "average partner has Y"), which must never be written, even as a future
   enhancement.
4. **GAME-05 — nothing is withheld from a partner who ignores this card.** No pipeline, chase
   list, or proposal behavior reads this card's state. The card has no write path at all (D-03:
   badges are derived, never persisted) — there is structurally nothing to gate behind engagement.

## Momentum, Streak & Badge Mechanics (the core of this phase's interaction design)

### The one shared window (D-10)

Both "this week's movements" and the streak read the **same** Monday–Sunday window, computed
**in Europe/Paris local time** — partners are in France; the server runs UTC. This is a
discretion call (`35-CONTEXT.md` § Claude's Discretion, "week boundary handling"): a fixed
`Europe/Paris` boundary (via `Intl.DateTimeFormat` with an explicit `timeZone`, not the server's
default UTC clock) is chosen over a raw UTC week so "d'ici dimanche" in the copy means the Sunday
the partner actually experiences, not a UTC Sunday that can be several hours off from their own.
**Do not introduce a second window definition anywhere** (D-10's explicit warning) — the streak's
"is this week alive" check and the movements list's "what's in this week" filter must call the
same boundary helper.

### What counts, and what is shown but doesn't count (D-01, D-11)

| Event | Shown in "this week's movements"? | Counts toward the streak? |
|---|---|---|
| Forward stage advance | Yes | Yes |
| Proposal finalized (client-linked) | Yes | Yes |
| Backwards stage move | Yes — same row styling as any other move (§ Color) | **No** |
| Move to `Perdu` | Yes — same row styling | **No** |
| Note added | No (D-01: notes never count, never appear here) | No |
| Next-action date set | No | No |

A week with only a backwards move or a `Perdu` move shows a non-empty movements list **and** a
streak sentence reporting the streak did not extend — this is the accepted, correct combination
(D-11's rationale: closing a dead deal is real work and belongs in the record, but it is not the
progress GAME-01 defines).

### Badge tier thresholds (Claude's Discretion, recorded per `35-CONTEXT.md`'s own instruction)

Chosen to be reachable from the zero-history state every partner starts in (D-14 — production has
almost no event history), while still giving a Gold rung worth reaching over months, not days.

| Axis | Bronze | Silver | Gold | Derivation |
|---|---|---|---|---|
| Clients | 3 distinct clients | 10 distinct clients | 25 distinct clients | Count of distinct relationships with ≥1 qualifying event (forward stage advance or proposal finalized), ever — derived from `relationship_events`, never persisted (D-03, D-07) |
| Wins | 1 win | 5 wins | 15 wins | Count of distinct proposals with a `won` outcome, ever |
| Consistency | 2 weeks | 6 weeks | 12 weeks | Longest streak ever reached (not just the current one) — GAME-03's "milestone reached," which a broken current streak must not erase, per D-07's "stays true forever" principle |

**These numbers are a starting point, not a locked contract** — recorded here specifically so
Antoine can adjust them without reopening the design. Changing a threshold is a constant edit,
never a migration (D-03).

### Momentum list truncation (Claude's Discretion)

Show up to **5** movement rows per week — the same cap `RelanceCard` and the recent-proposals
list already use elsewhere on this page. If more than 5 qualify, render the trailing plain-text
line "+ {n} autres mouvements cette semaine" (not a link — no dedicated "all movements" page
exists, and D-20 keeps this feature to the home page only).

### Placement relative to existing home-page content

Inserted **immediately after `<RelanceCard>` and before the recent-proposals card/list**
(Assumption A-1 below) — not appended at the very bottom of the page. D-04's rationale ("momentum
is the reward for having done it" — i.e., for having worked the chase list) reads best directly
beneath the thing it rewards.

## Surface-by-Surface Contract

### 0. Route map (unchanged)

No new route. `app/(authed)/page.tsx` gains one new child component and, for non-admin sessions,
2-3 new owner-scoped data calls folded into its existing `Promise.all`.

### 1. `MomentumCard` — `app/(authed)/page.tsx` (GAME-01..05)

Server component, no client directive — same posture as `RelanceCard` (renders links and text
only, nothing interactive on this surface needs to ship to the browser).

**Props**, mirroring `RelanceCard`'s shape:

```
interface MomentumCardProps {
  lang: Lang;
  nowMs: number;              // read ONCE on the server, same pattern as RelanceCard/ProposalRow
  streakWeeks: number;        // current streak, 0 if broken/never started
  movements: MomentumRow[];   // already owner-scoped, already window-filtered, already ordered
  badgeProgress: BadgeAxisProgress[]; // 3 axes × 3 tiers, earned flags pre-computed
  trackedSinceLabel: string;  // D-14's dynamic "septembre 2026" fragment, computed server-side
}
```

**Rendering rule for admins:** `app/(authed)/page.tsx` does not render `<MomentumCard>` at all —
not with empty props — when the session role is admin (§ Access & Non-Leakage point 2). This is a
conditional `{!isAdmin && <MomentumCard ... />}` at the call site, not a branch inside the
component, so an admin's request never even resolves the momentum queries.

**Composition inside the `Card`:**

```
<Card>
  <CardHeader>
    <CardTitle className="text-sm font-bold uppercase tracking-widest text-muted-foreground">
      {t('dashboard.momentum.title', lang)}
    </CardTitle>
  </CardHeader>
  <CardContent className="flex flex-col gap-4">
    {/* Part 1 — streak sentence, always rendered, D-12 */}
    <p>{streak sentence, one of the two variants in § Copywriting}</p>

    {/* Part 2 — this week's movements */}
    <div>
      <p className="text-xs ...">{t('dashboard.momentum.thisWeek', lang)}</p>
      {movements.length === 0
        ? <p className="text-muted-foreground text-[14.5px] m-0">{t('dashboard.momentum.empty', lang)}</p>
        : movements.map(row => <Link .../>)}
      {movements has more than shown: trailing "+N autres" text}
    </div>

    {/* Part 3 — badge ladder, always fully rendered, all 9 rungs readable (GAME-03) */}
    <div className="flex flex-col gap-1.5">
      {/* one row per axis */}
    </div>

    {/* Permanent disclosure — operator instruction */}
    <p className="text-xs text-muted-foreground">{t('dashboard.momentum.disclosure', lang)}</p>
  </CardContent>
</Card>
```

This is illustrative structure, not a literal file to paste — exact JSX/Tailwind class
composition is the executor's to finalize against `Card`'s real base class, matching the
typography/color/spacing tables above.

## Assumptions (confirm before execution)

1. **A-1 — Placement is immediately after `<RelanceCard>`, before the recent-proposals
   card/list.** `35-CONTEXT.md` D-17 says "below à relancer" and "nothing existing is displaced"
   without naming an exact ordinal against the recent-proposals card. This contract reads
   "displaced" as "not removed or resized," not "not reordered," and places `MomentumCard`
   directly beneath the card it rewards (D-04's own rationale). If the planner reads it as
   "append at the very bottom of the page instead," that is a one-line JSX move with zero
   downstream impact on this spec.
2. **A-2 — Badge tier thresholds (§ Mechanics) are the planner's/executor's starting numbers,
   not a locked contract.** Explicitly flagged by `35-CONTEXT.md` itself as Claude's Discretion,
   "reachable... record the chosen numbers so Antoine can adjust them." Treat a request to change
   a threshold as a constant edit, not a spec violation.
3. **A-3 — Week boundary is Europe/Paris, computed via an explicit-timezone helper, not the
   server's default UTC clock.** This is a discretion call recorded in § Mechanics. If the
   planner determines a raw UTC week is acceptable (e.g., because the few-hours edge case is
   judged not worth a timezone dependency), that is a defensible alternative **as long as the
   streak and the movements list use the identical boundary** — D-10's non-negotiable half of
   this decision.
4. **A-4 — Query/module naming (`momentum.ts`, function names) is implementation discretion.**
   Named here only for continuity; exact naming is the planner's call, same posture as
   `33-UI-SPEC.md`'s Assumption A-4.
5. **A-5 — "Longest streak ever" (not "current streak") is what the Consistency badge axis
   measures.** This follows D-07's "derive from events, not current state" principle: a
   currently-broken streak must not erase a Gold consistency badge earned three months ago. If
   the planner reads GAME-03 as wanting "current streak length" instead, that is a one-line
   query change, not a redesign — but note it would then conflict with D-07's own stated
   rationale for badges in general, so the "longest ever" reading is the one this spec commits to.
