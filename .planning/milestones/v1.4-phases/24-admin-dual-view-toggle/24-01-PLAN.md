<objective>
Build the session-only view-state foundation that the Admin/Agent toggle drives: a standalone `useSyncExternalStore` module over `sessionStorage['leasetic.view']`, the 4 i18n strings the toggle renders, and the logout-clear wiring that guarantees a fresh login always lands in Admin view.

Purpose: D-04 mandates `sessionStorage` (not React state) because D-01's redirect remounts the sidebar across route-group boundaries (C-01) — a pure in-memory flag would be wiped on the jump. Extracting the store into `src/lib/view-store.ts` lets BOTH `RetractableSidebar` (nav-set decision) and `ViewToggle` (display + setter, Plan 02) consume it. This plan is the dependency floor: Plan 02 imports everything created here.

Output: `src/lib/view-store.ts` (+ test), 4 new i18n keys (FR+EN), and a one-line-of-behavior change to `UserMenu.handleLogout`. Satisfies VIEW-03 (session-only, resets after logout).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → sessionStorage | The view flag is written/read entirely client-side; any user can edit `sessionStorage['leasetic.view']` via devtools. It is a NAV-ONLY hint, never an authorization input. |
| logout → session teardown | clearView() runs client-side after Better Auth signOut; the real session invalidation is server-side (signOut). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Elevation of Privilege | view-store.ts setView / sessionStorage | accept | The flag is consumed ONLY for nav-set selection in the client sidebar (Plan 02), never by any server authz path. A non-admin editing `leasetic.view='admin'` gains nothing: the real role gate (C-03) renders the toggle null for non-admins and the nav-set decision is `isAdmin && effectiveView==='admin'` — `isAdmin` is the server-derived real role, so a forged flag cannot produce the admin nav for a partner. Authorization (middleware + per-route requireAdmin) is untouched (C-04 / VIEW-04). |
| T-24-02 | Information Disclosure | clearView on logout | mitigate | clearView() removes the flag after signOut so a subsequent login on the same tab starts in Admin (VIEW-03) and no prior agent-preview state leaks across the session boundary. Server signOut remains the authoritative session teardown. |
| T-24-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs NO new packages (pure in-repo TypeScript + existing Vitest). No package-legitimacy checkpoint required. |
</threat_model>
