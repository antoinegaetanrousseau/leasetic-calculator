<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (sidebar) → nav-set selection | The view flag (client-controlled sessionStorage) selects which nav set renders. Untrusted input — but consumed only for navigation, gated by the server-derived real role. |
| server layout → client sidebar | (authed)/(admin) layouts forward isAdmin (real role), adminSegment (admin routes only), and adminHomeHref (admin redirect target). These are the trust anchors; the client flag cannot override them. |
| (admin) route group | Physical presence in /[adminSegment] forces effectiveView='admin' (D-02), independent of the flag. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-03 | Elevation of Privilege | RetractableSidebar nav decision | mitigate | The nav set is `isAdmin && effectiveView === 'admin' ? adminNav : partnerNav`. `isAdmin` is the server-derived real role (from requireUser/requireAdmin in the layouts, C-02). A non-admin forging `sessionStorage['leasetic.view']='admin'` cannot obtain the admin nav: `isAdmin` short-circuits the AND to partnerNav, AND ViewToggle is wrapped in `{isAdmin && ...}` so the toggle itself never renders for non-admins (C-03/VIEW-01). The nav set is cosmetic anyway — every admin link still hits a route protected by the unchanged (admin) layout (ADMIN_URL_SEGMENT match + requireAdmin), so even hand-crafted admin URLs are gated server-side (C-04/VIEW-04). |
| T-24-04 | Elevation of Privilege | agent view never drops privilege | mitigate | Agent view is a NAV remap only — no server authz keys off the view flag (no middleware/guard/route changes in this plan, asserted by the C-04 acceptance gate that no proxy/requireAdmin files appear in the diff). An admin in agent view retains full rights; directly opening an admin URL loads (authz unchanged, VIEW-04) and D-02 reconciles the sidebar to Admin. The view flag is never read server-side. |
| T-24-05 | Information Disclosure | ADMIN-09 commission invisibility in agent view | mitigate | Agent view renders the SAME partner route set that already exists; it introduces no new data surface. The Phase 22 ADMIN-09 grep-contract suite (commission structurally absent for Agent/Commercial across UI/calc/PDF/logs/audit) is unchanged and untouched by this plan — the toggle only swaps which nav links render, not any data query. ADMIN-09 invariant holds because no commission-bearing surface is added or altered. |
| T-24-06 | Information Disclosure | adminHomeHref leaks ADMIN_URL_SEGMENT to client | accept | The Admin-view redirect requires the `/[adminSegment]` path on the client (the sidebar cannot read process.env). adminHomeHref is forwarded ONLY when `role === 'admin'` (server-gated in the authed layout) — a non-admin's Shell never receives it, so the hidden segment is not disclosed to partners. Admins already know the segment (it is their own admin home URL). URL obscurity is explicitly NOT the security control (AUTH-15: requireAdmin is); exposing the segment to an authenticated admin is the existing accepted posture. |
| T-24-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs NO new packages (lucide-react, next/navigation, react, Vitest all pre-existing). No package-legitimacy checkpoint required. |
