**Accent reserved for:**
- `--teal`: Export button loading spinner, search field focus ring, AdminNavCard `openLabel` text, cursor pagination links
- `--gd` / `--gd-text`: PageHero eyebrow text (`ADMIN`), active filter pill background and section dot
- `--gold` / `--gold-text`: StatusChip `draft` variant in LC dashboard table ONLY (`.chip-draft`)
- `--danger`: StatusChip `deleted` variant ONLY (`.chip-deleted`)

**Export CTA button variant:** `.btn-out` (outline/ghost style — `background: transparent; color: var(--ink); border: 1px solid var(--border)`). This preserves the primary/secondary hierarchy: `Nouvelle proposition` keeps `.btn-green` (primary teal fill), `Exporter en XLSX` uses `.btn-out` (outline secondary). Loading state: button gets `disabled` attribute (opacity 0.6 per `.btn-out:disabled` CSS rule) + label swaps + inline Loader2 spinner in `var(--teal)` color.

**LC dashboard 4th AdminNavCard accent:** `--teal` RGB `45, 122, 140` (matches the existing `partners` variant). Rationale: `Hash` / `Receipt` icon represents a reference registry — teal is the closest semantic match among the 3 existing variants, and `--navy` (history variant) is already taken. The 4th card adds a new `variant` type `'lc-references'` with `{ rgb: '45, 122, 140', token: 'var(--teal)' }` — OR the executor may expand `AdminNavCard` to accept a generic `accent` prop rather than adding a 4th named variant, which avoids proliferating the variant union. Executor picks the cleaner approach.

**Dark mode:** All Phase 19 surfaces inherit dark via `html[data-theme="dark"]` token cascade. No per-component dark CSS. Light + dark ship together (v1.3 invariant #1).

### ExportButton — State Machine

This is a `'use client'` component (`ExportButton.tsx`) receiving:

| Success | Toast via sonner: `Export prêt` (FR) / `Export ready` (EN). Button returns to Default state. | |
| Error | Toast via sonner: `Échec de l'export, réessayez` (FR) / `Export failed, try again` (EN). Button returns to Default state. | |

## Interaction Contracts

### ExportButton interaction sequence

1. User clicks `Exporter en XLSX` (button enabled, `resultCount > 0`)
2. Button enters loading state: `disabled`, label → `Génération…`, `Loader2` spinner appears
3. Server Action executes: queries proposals, generates XLSX buffer, returns `Response` with `Content-Disposition: attachment`
4. Browser triggers native file download dialog / auto-download
5. On success: sonner toast `Export prêt`, button returns to default state
6. On error: sonner toast `Échec de l'export, réessayez`, button returns to default state
7. If `resultCount === 0` on SSR render: button rendered `disabled` with tooltip; no loading state possible

### LC dashboard search interaction

1. User types in search field → URL updates with `?q={value}` (form submit or router push)
2. Page SSR re-renders with filtered results
3. If results empty: empty-state with `Effacer la recherche →` link → clears `?q=` param

### LC dashboard pagination interaction

1. User clicks next/previous cursor link → URL updates with `?cursor={base64}` (Next.js `<Link>`)
2. SSR re-renders next/previous page of ~20 rows
