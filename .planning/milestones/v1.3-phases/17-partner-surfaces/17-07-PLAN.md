## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-07-01 | Tampering (cross-user draft update) | updateValidityAction | mitigate | Action calls `requireUser()` to get session.user.id; `getDraftById({ draftId, userId: session.user.id })` enforces ownership; if draftId belongs to another user, action returns `{ok:false, error:'not_found'}` |
| T-17-07-02 | Tampering (invalid validity value) | updateValidityAction days param | mitigate | Zod enum validates `days ∈ {15, 30, 60}` even though TS type narrows in client; defense against direct API invocation with attacker-controlled days |
| T-17-07-03 | Information disclosure (commission via step 3 preview) | wizard step 3 CALCUL recap | mitigate | The Phase 13 D-12 envelope is preserved — commission row in CALCUL is the allowed exception for the deal-owner partner; PdfPreviewMock is partner-side preview (no commission in its rendered output by construction — lcRef + loyer + validity only); ADMIN-09 9-gate suite verifies |
| T-17-07-04 | Information disclosure (lc_ref enumeration) | lcRef rendered in PdfPreviewMock | accept | lcRef is partner-scoped (allocated per-user sequentially per Plan 01); cross-partner enumeration not possible via this UI (deal-owner only); the format `LC-2026-NNN` is not a security secret |
| T-17-07-05 | Repudiation (validity change without audit) | updateValidityAction | accept | Per Phase 13 D-16 + Phase 17 CONTEXT Established Patterns, pre-finalize draft updates do NOT write to audit_log; validity selection is a draft input change, not a lifecycle event; lifecycle audit fires at finalize; ASVS L1 audit scope unchanged |

</threat_model>
