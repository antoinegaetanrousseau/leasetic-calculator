**Timezone library — no new dependency.** `date-fns@^4.4.0` and
`@date-fns/tz@^1.5.0` are both already in `package.json` `dependencies`

package-legitimacy gate applies. Hand-rolled `Intl.DateTimeFormat` offset
arithmetic is rejected: it is the classic source of off-by-one-hour DST bugs,
and this phase has two real DST-affected weeks per year.

`35-CONTEXT.md` Claude's Discretion "week boundary handling"). The copy says
"d'ici dimanche", which must mean the Sunday the partner in France actually
experiences.

`relationship_events` `INSERT … SELECT` fix (`62e26fa`) shipped, per the
ROADMAP's measured data constraint #1 and D-14. This is the date behind the

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| none crossed in this plan | These modules receive already-owner-scoped data as arguments and return plain values. No request, no session, no database, no I/O. |
| logic → downstream query layer | The week window this plan defines becomes the WHERE-clause bound that 35-02 compiles into an owner-scoped statement. A wrong window widens what is read, but never widens WHOSE data is read. |

| T-35-01-04 | Repudiation | streak fold | mitigate | Derivation is from append-only event weeks (D-07); no state is written, so there is nothing to falsify or lose. A reversal cannot un-earn a badge because `longestWeeks` is a max over history, never a current-state read. |
