# Phase 31.1 Plan 04: Container Radius Back-Application Summary

**Moved Card/Dialog/AlertDialog/Popover and the three Phase 31 review-queue surfaces onto the shared `--radius-container` token (16px via the `rounded-container` utility), retired the last three `rounded-[24px]` literals, and added a 5-assertion component-layer regression gate — closing OPEN-A.**

## Performance

- **Duration:** ~14 min
- **Started:** 2026-09-02T22:12:00+02:00 (approx, first read)
- **Completed:** 2026-09-02T22:26:31Z

## Accomplishments

- `card.tsx`, `dialog.tsx`, `alert-dialog.tsx`, `popover.tsx` roots switched from `rounded-2xl`/`rounded-4xl` to `rounded-container` — confirmed by the emitted build CSS to resolve to 16px (`.rounded-container{border-radius:var(--radius-container-sm)}`, `--radius-container-sm:16px`).
- `input.tsx`, `button.tsx`, `badge.tsx` (and `select.tsx`, checked via `tests/radius-scale.test.ts`) are byte-unchanged — the control tier is provably untouched.
- `PairReviewCard.tsx`'s wrapper div moved off its `rounded-[24px]` literal onto `rounded-container`; `MergeDialog.tsx`/`KeepSeparateDialog.tsx` dropped their `rounded-[24px]` className overrides entirely, now inheriting the radius from the primitive.
- Zero `rounded-[24px]` matches remain in `app/`/`src/` outside `components/blocks/` (verified by grep both before writing the test and as the test's own assertion 1).
- `tests/container-radius.test.ts` — new 5-assertion source-only test suite (recursive file walk, comment-stripped regex matching, no jsdom) that fails the build if any container surface drifts back to a px literal, a container primitive stops reading `rounded-container`, the two review dialogs regain a radius override, or a control primitive starts reading `radius-container`.
- Phase 30's `.card` (already on `--radius-container` from Plan 31.1-01) and Phase 31's `PairReviewCard`/dialogs now render at the identical 16px radius — OPEN-A is closed.

## Decisions Made

- Class form: `rounded-container`, confirmed generated by Tailwind from the `--radius-container` custom property (verified in the emitted `.next/static/chunks/*.css` before writing any class string), used identically in all seven files.
- `MergeDialog`/`KeepSeparateDialog`'s `className="rounded-[24px]"` overrides were deleted rather than rewritten to `rounded-container` — restating a value the primitive already supplies would be a second source of truth for the same corner.
- `src/components/proposal/segmented.ts`'s `rounded-[12px]` (a control literal on the shared `DurationSegmented`/`YesNoToggle` chrome, not a container surface) was discovered during the Task 3 literal sweep, was not in the plan's known allow-list, and was added to `tests/container-radius.test.ts`'s allow-list with an explanatory comment rather than retired — it is out of D-01/D-02's container-only scope for this plan.

**1. [Rule 1 - Bug] Reworded the three review-queue docblocks to avoid the literal `rounded-[24px]` substring**
- **Found during:** Task 2
- **Issue:** My first draft of the reworded `PairReviewCard.tsx`/`MergeDialog.tsx`/`KeepSeparateDialog.tsx` docblocks (explaining the retired literal in past tense) used the literal string `` `rounded-[24px]` `` — which matches the plan's own acceptance grep (`grep -rn "rounded-\[24px\]" app src | grep -v components/blocks/`), the exact class of self-tripping trap the tooling_warning called out and 31.1-01-SUMMARY.md hit with `calc(var(--radius)`.
- **Fix:** Reworded to "a hardcoded 24px corner literal" / "a hardcoded 24px corner override" — same historical meaning, no literal `rounded-[24px]` substring.

**2. [Rule 1 - Bug] Reworded `dialog.tsx`/`alert-dialog.tsx`'s Task 1 comments to avoid the literal `rounded-4xl` utility-class substring**
- **Found during:** Task 3, while running the constraint's "verify `rounded-4xl`/`rounded-3xl` usage is unaltered" grep as part of finalizing the container-radius test's allow-list
- **Issue:** Task 1's inline comments on `DialogContent`/`AlertDialogContent` quoted the Tailwind utility class name `` `rounded-4xl` `` (not the CSS custom property `--radius-4xl`) to describe what the root used to read. This made `grep -rln "rounded-4xl" app src` list `dialog.tsx`/`alert-dialog.tsx` even though neither file's className actually uses that class any more — polluting the plan's own "no rounded-4xl usage altered" verification and creating a false signal that the control-tier class survived in a container file.
- **Fix:** Reworded both comments to reference `` `--radius-4xl` `` (the CSS variable/token), matching `card.tsx`'s comment style, which already used the variable name rather than the utility class.
- **Files modified:** `dialog.tsx`, `alert-dialog.tsx`
- **Verification:** `grep -rln "rounded-4xl" app src | grep -v components/blocks/` no longer lists `dialog.tsx`/`alert-dialog.tsx`; the 14 real control-tier files (`input.tsx`, `button.tsx`, `select.tsx`, `badge.tsx`, etc.) are unaffected and still listed.
- **Committed in:** `583edd1` (Task 3 commit, alongside the new test file — these two files had already been committed once in `3c32ac1` for Task 1, so the fix necessarily lands as a follow-up commit rather than an amend, per the no-amend rule)

**3. [Rule 2 - Missing critical, scoped narrowly] Added `src/components/proposal/segmented.ts` to the container-radius test's allow-list**
- **Found during:** Task 3, full-repo grep for `rounded-\[\d+px\]` before finalizing the allow-list (the same verify-before-excluding discipline the plan's Task 2 constraint applied to the three retired literals)
- **Issue:** `segmented.ts` (shared chrome for `DurationSegmented`/`YesNoToggle`) carries `rounded-[12px]`, a literal not listed in the plan's known control-detail allow-list (`chart.tsx`, `tooltip.tsx`, `checkbox.tsx`, `reui/phone-input.tsx`, `reui/cascader/cascader-item.tsx`, `reui/gantt/*`). Without accounting for it, assertion 1 of `tests/container-radius.test.ts` would fail on a file this plan was never scoped to touch.
- **Fix:** Confirmed via its own header comment that this is a deliberate, pre-existing control-tier literal (a segmented radio group is a control, not a container — D-03 scopes this plan to containers only) and added it to the test's allow-list under a new `CONTROL_LITERAL_ADDITIONS` constant with a multi-line comment explaining why it's there and why it's out of scope for retirement in this plan.
- **Files modified:** `tests/container-radius.test.ts` (test-only; `segmented.ts` itself was NOT touched)
- **Verification:** `npx vitest run tests/container-radius.test.ts` — assertion 1 passes with the allow-list entry present and explained, not silently skipped.
- **Committed in:** `583edd1` (Task 3 commit)
