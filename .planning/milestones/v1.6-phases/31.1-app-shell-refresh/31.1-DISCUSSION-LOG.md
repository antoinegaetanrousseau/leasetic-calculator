## Colibris alignment (operator-added area)

The operator added a fifth area beyond the four proposed: "Similarity to Colibris style and
components."

`Colibris` appeared three times in the repo, all from v1.0 and all about the **dark palette**
(`Matrice_2026_THE_Leasetic-v10.html:28`, `MILESTONES.md:184`, `v1.0-ROADMAP.md:65`) — a direction
`globals.css:20-22` records as deliberately reverted "so the product reads as ReUI". That made the
ask ambiguous, so it was put back to the operator rather than guessed.

| Option | Description | Selected |
|--------|-------------|----------|
| Restore the Colibris dark palette | Move dark tokens back toward v10's `#0c121c` / `#161e2d` | |
| Colibris look across shell components | Palette plus sidebar density, nav treatment, header weight | |
| External reference — let me show you | Colibris is a product not in this repo | ✓ |
| Broader than the shell | Whole-app direction; flagged as a design-system phase, not this one | |

**User's choice:** External reference — `https://colibris-eosin.vercel.app`

**Notes:** The operator supplied three things that reframed the entire phase:
1. **Structure**, not palette, is what should match.
2. Colibris is **built on ReUI `base-maia` with a large radius** — the same design system, running
   the configuration Leasétic tried and reverted.
3. Rationale: *"I want the two apps to look alike because they are for the same teams and are
   meant to belong below a same group, even though they are technically from two separate
   brands/companies."*

The live app was then inspected directly. Colibris's own sidebar lists `Leasetic France`,
`Colibris SAS`, `Leasetic Iberia`, `Leasetic Benelux`, `Leasetic DACH` beneath a `Leasetic Group`
breadcrumb, corroborating the sibling-product framing.

**Measured, and it inverted the premise.** Colibris renders cards at **16px** and controls at
**8px** — its cards are *smaller*-radius than Phase 31's 24px literal and within 2px of Phase 30's
18px `.card`, and its control radius is *identical* to Leasétic's. Same typeface (Inter). Sidebar
252 vs 260px; collapsed rail 68 vs 72px. The two products were already close; what actually
differs is the **scale architecture** — Colibris declares explicit steps (12/16/24/32/40) where
Leasétic multiplies one token by 0.6…2.6.

## Dark mode

Asked as a scope question, then reopened after a factual error.

| Option | Description | Selected |
|--------|-------------|----------|
| Out of scope — structure only | Keep the phase inside its six criteria | |
| Check and match Colibris's dark palette | Expands scope; touches UIC-03 | ✓ |

**User's choice (first pass):** Check and match Colibris's dark palette.

**Agent error, and the correction.** A follow-up inspection reported *"Colibris has no dark
mode"* — based on scanning stylesheets for `prefers-color-scheme: dark`, `[data-theme=dark]` and
`.dark`, which returned 0 matches across 66 rules, with no theme toggle and an empty
`localStorage`. The operator corrected this with a screenshot of Colibris in dark mode.

The method was wrong for this app: Colibris has **~438 inline-styled elements against 2
stylesheets / 66 rules**, so its theme is JS state applied inline and is invisible to a CSS-rule
scan. Forcing `prefers-color-scheme: dark` plus a reload does not trigger it either, and the
toggle could not be located via `aria-label`, menu probing, or storage keys.

**Resolution:** the decision stands (match Colibris's dark palette), but the token values are
**deferred to research**, which must first ask the operator how to switch Colibris into dark mode.
Recorded as **D-13**, including the note that this expands the phase beyond its six ROADMAP
criteria and reopens UIC-03 — both of which need amending rather than quietly contradicting.
