<objective>
Make the `db-smoke` migration gate Phase 20 built actually fire, and actually fail, on the
regression it was built to catch.

**INFRA-04 is already satisfied — plan zero work for it.** Phase 20 (2026-05-27) shipped the
full three-branch Neon split: `main` / `preview` / `development` each with their own pooled
endpoint, and `db-migrate.yml` routes per-branch via `DATABASE_URL_MAIN` / `_PREVIEW` /
`_DEVELOPMENT`. The ID is carried on this plan for traceability only. Do not touch
`db-migrate.yml`, Vercel scopes, or Neon branch configuration.

**INFRA-06 is two defects, not one.**

Defect A — the gate does not fire. `.github/workflows/ci.yml`'s `db-smoke` job filters on
`drizzle/migrations/*.sql`. That directory does not exist; all seven migrations live directly at
`drizzle/NNNN_*.sql`. The pattern has never matched anything. The job still fires most of the
time via its second pattern, `drizzle/meta/_journal.json`, because `npm run db:generate` writes
both files together — which is exactly why the bug survived. A migration committed *without* a
journal entry matches neither pattern, so the job skips its internal steps and reports green.
It fails OPEN: "no schema change detected" is indistinguishable from "schema change checked and fine".

Defect B — the gate would not fail even if it fired. Verified against `scripts/migrate.ts`:
`drizzle-orm`'s `migrate()` applies entries from `drizzle/meta/_journal.json`. The `.sql` file
listing in `migrate.ts` is console output only and does not affect what is applied. An orphaned
`.sql` with no journal entry is invisible to the migrator — so `npm run db:migrate` against the
ephemeral branch succeeds and `db-smoke` goes green anyway. **Fixing the path filter alone does
not satisfy success criterion 1.** A journal/SQL consistency assertion is required, and it must
live inside the `db-smoke` job so the failure surfaces on the job named in the criterion.

Purpose: eight new migrations land in phases 30-34. The gate must be honest before they do.
Output: two `check:*` guard scripts, a corrected path filter, both gates wired into CI, and a
runbook section recording the scenario matrix.

**Explicitly out of scope (do not fix, do not let it fail your gates):**
`drizzle/meta/0005_snapshot.json` is absent — a residue of the Phase 22 journal repair recorded
in STATE.md. Drizzle's migrator never reads snapshots (only `drizzle-kit generate` does), so this
is inert. The journal-sync gate below must assert journal-entry ↔ `.sql`-file parity **only**,
never snapshot parity, or it fails on current HEAD for a non-defect.
</objective>
