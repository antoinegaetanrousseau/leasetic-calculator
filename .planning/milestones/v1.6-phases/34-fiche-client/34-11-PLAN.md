## Adapt by reuse means: import the primitives, leave the block alone

`src/components/blocks/solution-crm-5/components/activity-timeline.tsx` is a 380-line demo that
composes `@/components/reui/timeline`, `@/components/reui/frame`, `@/components/reui/badge`,
`@/components/reui/icon-stack`, a `ToggleGroup` type filter, and a `BUCKET_ORDER` / `bucketLabel`
day-bucketing helper that lives in its sibling `./data.tsx` (356 lines) alongside demo fixtures.

**Chosen: the new `ActivityTimeline.tsx` lives under `app/(authed)/clients/[id]/`, imports the ReUI
primitives directly, and re-implements the bucketing over real data.** It does NOT import from
`src/components/blocks/solution-crm-5/` at all, and it does not ship `data.tsx`'s demo fixtures.

Two reasons, both structural rather than stylistic:

1. `src/components/blocks/**` is ESLint-excluded (`eslint.config.mjs:32-37, :122-125`) for both the
   import-restriction layer and the SHELL-06 hardcoded-JSX-text layer. A timeline living there would
   ship untranslated strings with no gate catching it. Living under `app/(authed)/clients/[id]/` it
   IS linted, and every string must go through `t()`.
2. `solution-crm-5` is re-imported wholesale on any registry refresh (plan 34-03 just did exactly
   that with `-o`). Anything edited inside it is silently lost unless recorded in UI-CONVENTIONS'
   re-import table. Writing our timeline outside it means there is nothing to lose.

If anything inside `src/components/reui/timeline.tsx` must be edited to make this work, add a row to
`.planning/codebase/UI-CONVENTIONS.md`'s "Vendored ReUI modifications to re-apply after any
re-import" table in the same commit. Prefer wrapping and composing over editing.

## The filter is a lens, not a second stream

ACTV-01 forbids separate tabs for notes and system events. The type filter renders as a
segmented control with three options — `all` (default), `notes`, `system` — that filters ONE array
in place. It must not be implemented as two rendered lists with a visibility toggle, must not change
the ordering, and `all` must be the initial state so the first thing a partner sees is the mixed
stream. A test asserts the default state and that switching the filter and switching back yields
the identical DOM order.

## Day bucketing and the clock

Buckets are `today`, `yesterday`, `earlier`, in that order, using the three dictionary keys plan
34-01 minted (`clients.timeline.bucket.*`). "Today" is computed from a `nowMs: number` prop supplied
by the server component that renders this one — never from `Date.now()` during render. Same rule as
`ProposalRow` and plan 34-09's card: a clock read during client render makes the output depend on
the client clock and breaks react-hooks purity.

An empty `earlier` bucket renders nothing — no heading with no rows under it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored event body/payload → rendered DOM | partner-authored and registry-derived text crossing into the page |
| null actor → rendered attribution | a claim about who did something |
| client component → server action | caller-supplied note text and date |
| vendored ReUI (ESLint-excluded) → linted call site | the boundary where i18n and house rules start binding |
| client clock → rendered bucket | a derived value that must not depend on the browser |
