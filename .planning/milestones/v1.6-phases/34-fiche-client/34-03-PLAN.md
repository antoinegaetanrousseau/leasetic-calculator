<decision_record>
## The font this repo protects is **Inter**, not Plus Jakarta Sans

The institutional memory around ReUI installs is "shadcn init breaks the Plus Jakarta Sans font
that PDF rendering depends on." Read literally against today's tree that instruction would send an
executor looking for a `plusJakartaSans.variable` in `app/layout.tsx` that is not there, find
nothing, and conclude the check passed vacuously.

The measured state on 2026-09-03:

- `app/layout.tsx:2,20-24,58` imports `Inter` from `next/font/google` with
  `variable: '--font-inter'` and applies `cn('font-sans', inter.variable)`. Its doc comment records
  that Inter **replaced** the previously self-hosted Plus Jakarta Sans for the UI.
- `app/globals.css:212` and `:500` (inside `@theme inline`) both resolve
  `--font-sans: var(--font-inter), 'Inter', system-ui, sans-serif`.
- Plus Jakarta Sans survives in exactly one place: `src/lib/pdf/document.tsx:36-41` registers the
  `PlusJakartaSans` family from the TTFs in `public/fonts/`, and `app/layout.tsx`'s comment states
  the PDF typeface is deliberately NOT affected by the UI switch — changing it would re-baseline
  the PROP-17 byte-determinism contract and touch the glyph-coverage tests.

**So there are TWO font surfaces to protect, not one**, and the checks below name both explicitly:
the UI's Inter wiring (`layout.tsx` + `globals.css`) and the PDF's Plus Jakarta Sans registration
(`document.tsx` + `public/fonts/`). Task 2 turns both into a committed structural test so the next
phase does not have to re-derive this.

## `shadcn init` is never run

`components.json` already exists, already declares the `@reui` registry with the
`Authorization: Bearer ${REUI_LICENSE_KEY}` header, and already pins `style: base-maia`,
`iconLibrary: hugeicons` and the `@/components` aliases. `init` would rewrite it and rewrite
`app/layout.tsx`'s font import. Only `shadcn add` is run, and `git diff components.json` must be
empty afterwards.
</decision_record>
