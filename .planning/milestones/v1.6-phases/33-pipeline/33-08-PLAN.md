that the SIREN gate holds at the database layer independently of application code (D-07), and that
the conversion-rate formula returns the numbers plan 33-03 locked when run over a real mixed

with a fake `db()` cannot see.

record of it passing against the Neon development branch.

## Same file, its own describe block and its own fixtures

`33-CONTEXT.md`'s canonical refs say of `client-relationships.isolation.integration.test.ts`:
"Extend it rather than writing a parallel one." That is honoured literally — the Phase 33 proofs
live in this file, sharing its `DATABASE_URL_TEST` gate, its skip-by-default guard, its
`vi.mock('server-only')` shim, its `__resetDbForTests()` call and its `postgres` client
convention.

They do NOT share its `beforeAll`. The Phase 30 seed is asserted against by roughly a dozen existing
tests (relationship counts, contact visibility, the A-only probe); adding stages, outcomes, a SIREN
and five more proposals to it would put every one of those assertions at risk for no benefit. The
Phase 33 block therefore declares its own `describe` with its own `runId`-scoped fixtures and its own
FK-safe `afterAll`. One file, one gate, two independent fixtures — which is what "not a parallel
one" was protecting against (a second skip-gate and a second harness to keep in sync), not a second
`beforeAll`.

## This plan does not exercise the server actions

`markProposalWonAction` needs a Better Auth session, which this harness has no way to construct. The
application half of the SIREN gate is unit-tested in plan 33-04 with a mocked `db()`; the database
half is proven here with no application code at all. Belt and braces are each tested where they can
be tested, which is exactly what D-07's two-layer design is for. Do not attempt to import
`src/lib/pipeline/actions.ts` here — the `'use server'` directive and the auth gate will fail
outside a Next request scope.

## Why the live run is a checkpoint

`.env.local` in this repo points at a shared Neon branch that is NOT the development branch (see
`docs/operations/neon-branch-routing.md`). An agent must not pick a connection string for this test.
The operator supplies the development-branch URL and runs the command, exactly as plan 33-02's apply
was an operator action.
