<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| request → route | an unauthenticated or wrong-role visitor reaching a partner surface |
| session → query arguments | the only legitimate source of an owner id |
| server-rendered props → client components | data that has crossed the owner scope once and must not be re-widened |
| role → rendered surface | a role branch would create two surfaces to secure instead of one |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-33-09-01 | Elevation of Privilege | an admin reading partner relationship data via `/pipeline` | high | mitigate | `requireRelationshipHolder()` is the first await and `notFound()`s on `role === 'admin'`; task 2 asserts both the 404 digest AND that neither query ran, so a fetch-then-hide implementation fails the suite. |
| T-33-09-02 | Elevation of Privilege | an owner id sourced from a search param, header or cookie instead of the session | high | mitigate | Both queries take `session.user.id` literally; `grep -c "session.user.id"` must return 2, and task 2 asserts the argument equals the mocked session id exactly. The page accepts no `searchParams`. |
| T-33-09-03 | Information Disclosure | a cross-partner aggregate reaching the tile (D-12) | high | mitigate | The tile's numbers come only from `getConversionRateForOwner(session.user.id)`; exactly one `MetricTile` renders (grep-asserted), and acceptance step 6 checks the rendered page for any cross-partner number. |
| T-33-09-04 | Information Disclosure | a 403 or other status confirming the route exists to a non-holder | medium | mitigate | `notFound()` produces a 404 identical to a nonexistent route; task 2 asserts the 404 digest and that no other client-error status is produced. |
| T-33-09-05 | Denial of Service | the board shipping mouse-only, excluding keyboard users | high | mitigate | Acceptance step 5 is a blocking, explicitly-reported gate (33-UI-SPEC A-5), with escalation required rather than approval-with-caveat. |
| T-33-09-06 | Tampering | a proposal outcome silently advancing a relationship to `signe` | high | mitigate | Acceptance step 13 checks D-04's Decoupling Contract on the running app; plan 33-04's grep gate and plan 33-06's page test cover it in code. | T-33-09-SC | Tampering | npm/pip/cargo installs | low | mitigate | No new dependency and no registry pull anywhere in this plan. `git diff package.json package-lock.json components.json` must be empty. |
