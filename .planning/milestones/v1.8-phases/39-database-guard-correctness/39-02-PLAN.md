<interface_contract>
This module's exports are consumed by plans 39-03, 39-04 (as the semantics bash must reproduce) and
39-05. The signatures are fixed here.

```
export function envFileOrder(nodeEnv: string): string[]
```
Returns the candidate filenames (bare names, NOT joined to any directory), highest precedence
first. For `nodeEnv === 'test'` the returned array is `['.env.test.local', '.env.test', '.env']` —
`.env.local` is excluded outright, matching `@next/env`. For every other value X the array is
`['.env.X.local', '.env.local', '.env.X', '.env']`. Callers must treat the array as
first-writer-wins.

```
export interface EnvResolution {
  url: string;
  /** '.env.production.local' | ... | 'process.env' — never a path, never a credential. */
  source: string;
}

export function resolveDatabaseUrl(opts: {
  cwd: string;
  nodeEnv: string;
  processEnv: NodeJS.ProcessEnv;
}): { resolution: EnvResolution | null; filesFound: string[] }
```
- `filesFound` lists, in precedence order, which of `envFileOrder(nodeEnv)` actually exist under
  `cwd`. It is what callers use to implement the local-only SKIP rule (empty ⇒ no local env files
  ⇒ this is a CI or build machine).
- `resolution` is `null` when nothing defines a non-empty `DATABASE_URL`.
- If `opts.processEnv.DATABASE_URL` is a non-empty string it wins and `source` is `'process.env'`.
- Otherwise the first file in `filesFound` whose parsed contents assign a non-empty `DATABASE_URL`
  wins, and `source` is that bare filename.
</interface_contract>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dotenv file on disk → resolver process | file contents are attacker-shaped in the sense that a malformed or hostile line must not execute |
| resolver return value → caller's log output | `EnvResolution.url` is a live credential; anything that prints it is an information disclosure |
| test fixture dir → repo working tree | a test that resolves a repo-relative path would read (and could clobber) the developer's real secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-02-01 | Elevation of Privilege | env file parsing | mitigate | Values come from `dotenv.parse` on a string read with `readFileSync`. No `source`, no `eval`, no `require`, no shell (D-08). Acceptance criterion greps for all four. |
| T-39-02-02 | Information Disclosure | `EnvResolution.url` | mitigate | Module prints nothing (greped `console.*` count is 0); docstring states `url` must only be used to derive `new URL(url).hostname`. Callers in 39-03/39-04 print hostname + `source` filename only (D-07). |
| T-39-02-03 | Information Disclosure | test fixtures | mitigate | Fixtures use `postgres://fixture:fixture@` placeholders; `grep` for `process.cwd` and `process.env` in the test file must return 0, so no case can reach a real credential (D-06, D-08). |
| T-39-02-04 | Tampering | repo `.env*` files | mitigate | All fixture paths are `mkdtemp`'d; `git status --porcelain` is asserted clean after the run (D-06). |
| T-39-02-05 | Denial of Service / fail-open | missing or empty files | mitigate | `resolveDatabaseUrl` returns `resolution: null` rather than a guessed value; `filesFound: []` is the explicit local-only SKIP signal, so a caller that forgets to handle `null` gets a type error, not a silent pass. |
| T-39-02-06 | Spoofing | ambient `DATABASE_URL` in the vitest process | mitigate | `processEnv` is an explicit parameter, never read from the ambient environment inside the module or the test — so a developer's exported `DATABASE_URL` cannot make a precedence test pass for the wrong reason. |
| T-39-02-SC | Tampering | npm/pip/cargo installs | mitigate | No package is installed. `dotenv` is already a declared dependency consumed by `scripts/_load-env.ts`; no new supply-chain surface. |
</threat_model>
