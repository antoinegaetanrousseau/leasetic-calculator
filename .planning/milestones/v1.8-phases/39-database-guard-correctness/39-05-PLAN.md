`tests/_db-guard-fixtures.ts` is a helper module, NOT a test file — `vitest.config.ts`'s include glob
is `tests/**/*.test.ts`, so a `.ts` file without `.test` is typechecked and linted but never
collected as a suite. It exports:

```
export interface GuardCase {
  name: string;
  nodeEnv: string;
  /** filename -> file body. Bodies use fake credentials only. */
  files: Record<string, string>;
  /** extra process env for the spawned guard; DATABASE_URL only when the case is about it. */
  env?: Record<string, string>;
  expect:
    | { kind: 'skip' }
    | { kind: 'ok'; host: string; source: string }
    | { kind: 'warn'; host: string; source: string }
    | { kind: 'error'; host?: string; source?: string; contains?: string[] };
}

export function makeFixtureDir(files: Record<string, string>): string;
export function cleanupFixtureDir(dir: string): void;
export function runGuard(dir: string, nodeEnv: string, env?: Record<string, string>):
  { status: number; stdout: string; stderr: string };
export const CASES: readonly GuardCase[];
```

`CASES` is the single case matrix, consumed by BOTH test files. Adding a case there extends the
exit-code proof and the differential proof at once.

Fixture hostnames are the three public DNS names from `docs/operations/neon-branch-routing.md`.
Fixture credentials are always the literal `fixture:fixture`, and every fixture connection string
carries the query fragment `?sslmode=require&secretmarker=MUSTNOTAPPEAR` so "no credential leaked"
is provable rather than asserted.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test fixture dir → repo working tree | a test resolving a repo-relative path would read the developer's real secrets and could clobber `.env.local` |
| vitest process env → spawned guard | an inherited `DATABASE_URL` would make precedence cases pass for the wrong reason, producing false assurance |
| test output → CI logs | vitest prints assertion diffs on failure; a real credential in a fixture would be published to GitHub Actions logs |
| documentation → operator | a doc that describes a guard behaviour the code does not have is the class of defect OPS-05 itself is (`_load-env.ts`'s false docstring) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-05-01 | Information Disclosure | fixture credentials in CI logs | mitigate | Every fixture uses `fixture:fixture` and a `secretmarker=MUSTNOTAPPEAR` query fragment; a dedicated invariant test asserts no case's output contains `MUSTNOTAPPEAR`, `fixture:fixture`, `postgres://` or `sslmode` (D-06, D-08). |
| T-39-05-02 | Tampering | repo `.env*` files | mitigate | Every path is under `mkdtemp`; `grep` for `process.cwd` in both test files must return 0; `git status --porcelain` and an `ls -a` env-file census are asserted after the run (D-06). |
| T-39-05-03 | Spoofing | inherited `DATABASE_URL` | mitigate | The spawned child's `env` is constructed as `{ PATH }` plus the case's own vars; `grep -c '...process.env'` in the harness must be 0. Otherwise a developer's shell could make a failing guard look passing. |
| T-39-05-04 | Elevation of Privilege | spawning a shell from a test | mitigate | `execFileSync('bash', [absolutePath, ...])` with an argv array — never `exec` with a concatenated command string, so a fixture directory name containing shell metacharacters cannot be interpreted. The guard path is resolved from `import.meta.url`, not from a mutable cwd. |
| T-39-05-05 | Tampering | resolver drift after this phase | mitigate | The differential suite is proven to BITE: a deliberate perturbation of the bash `test` node-env order must fail it before the change is reverted. A test that has never been seen to fail is not evidence. |
| T-39-05-06 | Repudiation | documentation drifting from behaviour | mitigate | The doc task's acceptance criteria grep for the specific behaviours claimed (`prebuild`, `--node-env`) so the doc cannot claim a flag the guard does not have. |
| T-39-05-07 | Denial of Service | temp-dir leakage | mitigate | `rmSync(dir, { recursive: true, force: true })` in `afterEach`, guarded on the dir being set; `ls /tmp \| grep -c '^db-guard-'` asserted to be 0 after the run. |
| T-39-05-SC | Tampering | npm/pip/cargo installs | mitigate | No package is installed. `node:child_process`, `node:fs`, `node:os`, `node:path` and `node:url` are stdlib; no new supply-chain surface. Any future install requires a blocking human legitimacy checkpoint. |
</threat_model>
