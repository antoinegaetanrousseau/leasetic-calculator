<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client input → server action | Every action in scope receives ids and field values from an untrusted client. |
| session role → authorization decision | `requireUser()` / `requireAdmin()` is the only sanctioned source of caller identity and role. |
| partner A's relationship facts → partner B | FICHE-04's privacy boundary over a company both partners may hold a relationship on. |
| scoped review document → future reader | A partial review mistaken for a full one is itself a security failure of the record. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-04-01 | Spoofing | a scoped review read as a full review | mitigate | `depth: scoped` in the frontmatter, an exhaustive `files_reviewed_list` whose length must equal `files_reviewed`, and a `## Summary` opening that names both the scope decision and what was NOT examined. Acceptance criteria assert all three and require every listed path to resolve. |
| T-37-04-02 | Elevation of Privilege | a Phase 34 server action trusting a client-supplied id without an ownership re-check | mitigate | Risk area 3's first check requires `requireUser()`/`requireAdmin()` as the first await before any input-derived identifier is used; such a defect is classified Critical by the plan, not left to reviewer discretion. |
| T-37-04-03 | Information Disclosure | FICHE-04 private relationship facts reachable by another partner on the same shared company | mitigate | Risk area 1 requires an explicit verdict on the shared-vs-private split, reviewed at the query layer (`src/lib/db/queries/client-relationships.ts`) rather than at the page, plus a check that no action returns private facts in an error payload. Plan 37-03's FICHE-04 truth covers the same boundary independently. |
| T-37-04-04 | Tampering | SQL injection or unconstrained event kinds on the `relationship_events` write path | mitigate | Risk area 2 requires verdicts on parameterisation (any string-interpolated identifier or value is Critical) and on constrained event-kind values. |
| T-37-04-05 | Repudiation | an ACTV-02 event written without actor or timestamp, or a shared-field edit with no audit-log entry | mitigate | Risk area 2 requires that actor and timestamp cannot be omitted; risk area 3 requires the FICHE-03 audit-log write to be present on every shared-field edit path including SIREN correction, and to be un-reachable-around. |
| T-37-04-06 | Repudiation | a review with no anchor to a tree state | mitigate | `reviewed_at_commit` from `git rev-parse HEAD` plus an ISO-8601 `reviewed` timestamp. |
| T-37-04-07 | Denial of Service | the review absorbing Phase 37 through fix-and-re-review rounds | mitigate | D-37-03 scopes the review; this plan forbids source edits outright and routes even a Critical to the operator as a decision point in the SUMMARY. Acceptance asserts `git status --porcelain` lists only the review document. |
| T-37-04-08 | Tampering | a reviewer silently repairing a finding, producing a review of code that no longer exists | mitigate | Same `git status --porcelain` assertion, plus `reviewed_at_commit` pinning the reviewed tree state. |
| T-37-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no packages and touches no `package.json`. |
