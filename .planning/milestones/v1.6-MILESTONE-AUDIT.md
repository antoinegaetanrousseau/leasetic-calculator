## Cross-Phase Integration — verified, 0 blockers

1. **Migration safety net holds under four later migrations.** All of
   `0007_phase30_crm_registry.sql` … `0010_phase34_fiche_client.sql` are present and
   journaled (11 entries, indices 0-10, all matching real files). The `db-smoke`
   `paths-filter` fix (INFRA-06) is live at `.github/workflows/ci.yml:94-97`, now backed by
   an anti-rot test (`scripts/check-db-smoke-filter.sh`) that parses the CI YAML itself.
   Phases 36 and 39 **hardened** this area rather than invalidating it.

2. **One registry, consumed everywhere — no shadow tables.** `src/db/schema.ts` is the
   single schema file; every later phase adds columns to the same `companies` /
   `clientRelationships` / `contacts` / `relationshipEvents` tables. Phase 31's
   reconciliation writes into them (`src/lib/reconcile/apply.ts:98,125,165`), Phase 33's
   pipeline reads off them (`src/lib/db/queries/pipeline.ts`), Phase 34's fiche renders
   from them.

3. **The `proposals.inputs` snapshot invariant is intact.** The reconciliation apply path's
   only proposal write is a single-column `.set({ clientRelationshipId })`
   (`src/lib/reconcile/apply.ts:302-304`); `clientRelationshipId` is deliberately absent
   from `UpdateDraftArgs`/`FinalizeDraftArgs` so no later wizard step can move it; Phase
   33's win/loss actions only set fresh top-level columns. Nothing mutates a saved snapshot.

4. **Win/loss reaches the fiche and the timeline.** `markProposalWonAction`
   (`src/lib/pipeline/actions.ts:355-419`) re-proves ownership *and* `isNotNull(companies.siren)`
   immediately before the UPDATE, then writes an `outcome_set` event that the fiche's
   `ActivityTimeline` renders.

5. **The E2E chain closes at every hop.** Client page → `/proposals/new/parametres?clientRelationshipId=`
   (ownership-validated) → finalize writes `proposal_finalized` → `/pipeline` board reads the
   same rows and links back to `/clients/{id}` → win re-validates SIREN + ownership → fiche
   renders header, four tabs, outcome control and full timeline → follow-up returns via
   `RelanceCard` on the home page.

6. **Phase 30's deferred admin-bypass item is closed.** `app/(authed)/proposals/[id]/page.tsx`
   had no admin bypass, so admins clicking through from an admin relationship-detail page
   404'd. Phase 37 (GAP-01) fixed it via a single source of truth,
   `src/lib/auth/proposal-access.ts:63-73`, with `!proposal` kept as an independent
   fail-closed short-circuit ahead of the role check. 11/11 tests pass, including the four
   GAP-01 cases. A drifted second copy of the same rule in the PDF route was subsequently
   unified onto the same module.

**Live evidence:** 52 live-Postgres integration tests (34 owner-isolation assertions) plus
55 guard/probe tests pass; lint clean.

and `/companies/review` (`src/lib/route-meta.ts:13-21,84-205`) — but a coverage figure
computed from REQ-IDs cannot see any of it.

and `28-CONTEXT.md`. This is recorded in `ROADMAP.md` as "Complete (retro-documented, outside
